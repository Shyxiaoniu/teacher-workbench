# QuickForm 教师版 2.5 —— 一键启动说明

双击即可运行，**不需要安装 Python、不需要联网、不需要敲命令**。

## 一、文件放在哪里

| 文件 / 目录 | 位置 | 作用 |
|---|---|---|
| `启动QuickForm.command` | 项目根目录（与 `app.py` 同级） | **macOS 双击入口** |
| `启动QuickForm.bat` | 项目根目录（与 `app.py` 同级） | **Windows 双击入口** |
| `scripts/start.py` | 项目根目录 `scripts/` | 启动器主逻辑（环境检测、装包、端口、日志、开浏览器） |
| `runtime/` | 项目根目录 | 随项目分发的可移植 Python 3.11.18（**macOS Apple 芯片版 + Windows 64 位版，依赖已预装**） |
| `logs/` | 自动生成 | 每次启动一个日志文件 `quickform-年月日-时分秒.log` |
| `scripts/_build_offline.sh` | 项目根目录 `scripts/` | 打包脚本：换机器/补平台时用它重建 `runtime/`（需联网，仅构建时用） |

> 启动脚本必须和 `app.py` 在同一级目录；移动/改名整个项目文件夹不影响使用（启动器按自身路径定位项目根目录）。

## 二、怎么用

### macOS
1. 双击 `启动QuickForm.command`。
2. **首次运行**可能被系统拦截，提示"无法打开，因为来自身份不明的开发者"：
   - 在访达中 **右键 → 打开 → 打开**，一次授权后以后双击即可；
   - 或执行一次：`xattr -dr com.apple.quarantine "/path/to/QuickForm 2.5"`。
   - 脚本本身每次启动也会自动清理 `runtime/` 的隔离属性，但系统仍会对脚本本身做一次校验，所以第一次右键打开是免不了的。
3. 依赖已随运行时预装，**启动即用（实测冷启动到浏览器约 8 秒）**。
4. 成功会自动打开 `http://127.0.0.1:5001/`；关闭终端窗口或按 `Ctrl+C` 停止服务。

> **Intel Mac 用户注意**：本包只内置 Apple 芯片（M 系列）运行时。Intel Mac 上运行时缺失，启动器会提示"请在 Intel Mac 上安装 Python 3.8-3.11"，此时装一个 python.org 的 Python 3.11 即可正常运行（依赖仍需联网安装一次）。若要彻底离线，在联网机器上执行 `bash scripts/_build_offline.sh --with-intel` 重新打包。

### Windows
1. 双击 `启动QuickForm.bat`。
2. 若出现"Windows 已保护你的电脑"(SmartScreen) 提示：点 **更多信息 → 仍要运行**（仅首次）。
3. 若杀毒软件拦截 `runtime\win-x64\python\python.exe`，将其加入白名单。
4. 依赖已随运行时预装，启动即用，同样不联网。

## 二点五、体积与精简

当前整包 **457 MB**（已精简，原打包态为 1.0 GB）：

| 目录 | 大小 | 说明 |
|---|---|---|
| `runtime/mac-arm64` | 235 MB | Apple 芯片 Mac，依赖已预装 |
| `runtime/win-x64` | 216 MB | 64 位 Windows，依赖已预装 |
| `static/` + `templates/` + `translations/` | 5.2 MB | 前端资源与翻译，必需 |
| `data/` | 464 KB | SQLite 数据库 |
| 其余 | <100 KB | 代码与脚本 |

已从运行时中删除的（均为运行期用不到的部分，共省 543 MB）：
- Intel Mac 运行时（`mac-x64`）与三平台离线 wheel 包（`wheels/`）
- 每个运行时的 `__pycache__`、各依赖自带的 `tests/`、`ensurepip`、`idlelib`、`lib2to3`、`pydoc_data`、`tkinter` + `tcl`、C 头文件 `include/`、Windows 的 `libs/`

> **`distutils` 必须保留**：setuptools 84 仍会 `import distutils`，删掉会导致 `ModuleNotFoundError`。打包脚本已注明，请勿再裁。

还可以继续按需精简：
- 只要 macOS，不要 Windows → 删 `runtime/win-x64`，整包降到 **241 MB**
- 需要 Intel Mac 或 wheel 兜底 → `bash scripts/_build_offline.sh --with-intel --with-wheels`（联网构建，约 1.0 GB 回滚）

## 三、启动器做了什么

1. **环境检测**（按顺序复用，命中即用）：
   **内置运行时 → 项目内 `.venv` / `venv` / `env` → 系统 `python3` / `python`**。
   内置运行时排第一是因为它是唯一保证依赖齐全、且探测最快的候选；若排在系统 Python 之后，新设备上要先把系统里的 Python 逐个真 import 一遍才淘汰，实测白白多花 20~30 秒。
   每个候选都会校验 `flask / pandas / matplotlib / requests / qrcode / PIL ...` 共 13 个模块，缺哪个就直接淘汰，不会出现"看起来能跑、点进去报错"。内置运行时用轻量校验（只查模块是否在位，不做真正 import），因为它的依赖是打包时验证过的——真正 import 一次要 6 秒（光 `flask_babel` 就 4 秒），而应用启动时还会再导入一遍，没必要重复付这个时间。
2. **离线补包（仅作兜底）**：只有内置运行时缺依赖时才尝试用本地 wheel 安装（`--no-index` 绝不联网）。精简版没有 `wheels/`，此时会明确提示"运行时依赖不完整，请重新解压原始包，或用 `scripts/_build_offline.sh` 重建"。
3. **端口检查**：默认 5001；若被占用会打印占用进程（`lsof` / `netstat`），并提供三个选项：结束占用进程 / 换端口 / 退出。非交互模式自动换端口。
4. **日志**：控制台输出实时打印，同时写入 `logs/quickform-<时间戳>.log`；失败时自动回显最后 30 行并给出日志路径。
5. **健康检查 + 开浏览器**：轮询 `http://127.0.0.1:<端口>/`，返回正常才调用 `open` / `os.startfile` 打开浏览器，并打印局域网访问地址。
6. **目录自检**：自动创建 `logs/`、`data/`、`static/uploads/`、`static/assets/`；目录不可写时给出明确提示（不要把项目放在只读目录或受管控的 `Program Files` 下）。

## 四、两个系统的差异（重点）

| 差异点 | macOS | Windows |
|---|---|---|
| 双击入口 | `.command`（可执行文件，需 `chmod +x`，已设置好） | `.bat`（无需可执行位） |
| 首次放行 | 右键 → 打开（Gatekeeper 隔离属性） | SmartScreen "仍要运行"、杀软白名单 |
| 脚本编码 | **UTF-8 + LF** 换行，中文可直接写 | `.bat` 保持**纯 ASCII**，中文全部由 Python 输出；靠文件首行 `chcp 65001` 正确显示 UTF-8 |
| 换行符 | 必须 LF；若变 CRLF 会报 `bad interpreter` | CRLF / LF 均可 |
| 路径分隔符 | `/`；目录含空格必须加引号 | `\`；`%~dp0` 末尾自带 `\`，所有路径加引号 |
| 解释器路径 | `runtime/mac-arm64/python/bin/python3` | `runtime\win-x64\python\python.exe` |
| 架构判断 | `platform.machine()` → `arm64` 命中内置运行时；`x86_64` 视为未提供（Intel Mac 需自装 Python） | 内置运行时固定 x86_64；ARM 版 Windows 可经 x64 仿真运行，32 位 Windows 不支持 |
| 端口占用查询 | `lsof -nP -iTCP:5001 -sTCP:LISTEN` | `netstat -ano -p TCP` + `taskkill /F /PID` |
| 结束进程 | `kill -9 <pid>` | `taskkill /F /PID <pid>` |
| 中文终端乱码 | 一般无问题；脚本已导出 `LANG/LC_ALL` | 由 `chcp 65001` + `PYTHONUTF8=1` 保证 |
| 杀软 / 隔离 | quarantine 属性 | Defender/SmartScreen，可能拖慢首次启动 |

打包分发注意事项：
- **必须整包压缩**：`runtime/`、`scripts/`、`app.py` 缺一不可，去掉任何一个都无法离线启动。
- Windows 下打包成 zip 时避免用会破坏 UTF-8 文件名的老工具；建议用系统自带"压缩"或 7-Zip。
- macOS 打包 zip 前先执行：
  `xattr -cr "/path/to/QuickForm 2.5"` 清理隔离属性，可显著减少用户侧的拦截概率。
- 若通过网盘分发，确保下载客户端不会自动丢掉 `__MACOSX` 之外的隐藏目录（如 `.venv`）。

## 五、常见问题

- **提示端口 5001 被占用**：多半是之前启动的 QuickForm 没关。选 `1` 结束占用进程，或选 `2` 换端口（换端口后，任务中的 API 地址也会变，需要重新生成/替换页面里的 API 地址）。
- **提示"内置运行时的依赖不完整"**：说明 `runtime/<平台>/` 被改动或没解压完整。精简版没有 `wheels/` 无法自动补装，重新解压原始压缩包即可。
- **首次启动会不会很慢**：不会。依赖已预装，实测从双击到浏览器打开约 7 秒。
- **想换端口常驻**：`scripts/start.py --port 8080`，或在 `.env` 里加 `PORT=8080`。
- **不想自动弹浏览器**：`scripts/start.py --no-browser`。
- **看不到日志**：所有输出都在 `logs/` 目录，按时间戳命名，永不覆盖。
- **用 wst / quickform 登不进去**：项目自带的 `data/quickform.db` 里已经存在账号（本副本为 `Yaxfenst`），而不是 README 里写的默认 `wst`；程序也不会在空库时自动建号。解决办法二选一：
  1. 删掉 `data/quickform.db`（连同 `-wal` / `-shm`），重启后自动重建空表，再用「QuickForm.cn 登录」走在线认证；
  2. 保留现有数据库、用已有账号登录，登录后在「个人中心 / 系统初始化」里把账号重置为 `wst / quickform`。

## 七、已知项目自身问题（非启动脚本引起）

- 随包分发的 `data/quickform.db` 含有他人遗留账号，存在隐私风险，分发前建议清空数据库。
- `config.py` 里 `SECRET_KEY` 走 `.env`，但 `.env` 被一起打包发布，等于密钥公开；分发前请重新生成 `SECRET_KEY`。
- 原 `app.py` 端口写死 5001，本次已改为读取环境变量 `PORT` / `QUICKFORM_PORT`（默认仍为 5001），其余业务逻辑未改动。

## 六、内置依赖清单（已预装在运行时里）

`runtime/mac-arm64` 与 `runtime/win-x64` 各预装 **38 个包**（两平台清单一致，均为对应平台的二进制 wheel），对应 `requirements.txt`：
Flask 3.0.3、Flask-Login 0.6.3、Flask-SQLAlchemy 3.1.1、Flask-Bcrypt 1.0.1、Flask-Babel 4.0.0、
SQLAlchemy 2.0.45、bcrypt 5.0.0、python-dotenv 1.0.1、pandas 2.0.3、matplotlib 3.7.5、
requests 2.32.4、qrcode 8.0（含 Pillow）。
内置运行时为 CPython **3.11.18**（python-build-standalone），选择 3.11 是因为上述版本组合在该版本上有官方二进制 wheel，可完全避免源码编译。
