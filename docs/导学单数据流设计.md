# 导学单数据流设计（学生零配置 · 教师端统一配置）

> 版本 v1.0 ｜ 2026-11-01 ｜ 对应工作台 2.0
>
> 一句话：**数据服务地址、任务号、学生身份，一个都不出现在学生页面上。**
> 教师端配一次，学生点开即用，答完自动进大屏。

---

## 1. 为什么改这一版

原来的做法是「谁提交，谁自己配」：导学单页面底部有个「连接教师端」按钮，学生要把
`http://192.168.123.51:5055/api/信息科技01` 这样的地址手填进去，还要填学号姓名。

三个现实问题：

| 问题 | 后果 |
|---|---|
| 地址要发给每个学生 | 换个入口/换台电脑、换一个端口，全班重填一遍 |
| 学生自带身份字段 | 学号打错、填成同桌的、或者干脆乱填，大屏数据不可信 |
| 地址写死在页面里 | 页面成了「一次性的」，第二年换个环境就不能用 |

这一版把配置**上收到教师端**，学生端只保留「点开」和「答题」两个动作。

---

## 2. 职责边界

| 角色 | 负责什么 | 在哪做 |
|---|---|---|
| **教师端（工作台）** | 活动数据服务地址、活动任务、导学单条目与发放状态 | 教师端「活动」页 + 「导学单」编辑 |
| **服务端（工作台进程）** | 验学生身份、签票、把提交转发给活动服务 | 自动，老师无感 |
| **学生端（今日页）** | 显示导学单、点「进入活动」 | 学生端「今日 · 导学单」 |
| **导学单页面** | 答题、提交 | 自动，学生无感 |

**唯一需要人工填写的，只有教师端的两处**：

1. 「活动」页右上 → *设置服务地址*（形如 `http://192.168.123.51:5055`），一次就好，会存进服务端配置；
2. 导学单条目里绑定活动任务（下拉选，不用手打）。

## 3. 一次完整的链路

```
① 教师端：活动页配服务地址 ──► 服务端 config.json  activity.api_base
② 教师端：选活动任务，加入导学单条目 ──► guides.items[n] = {type:activity, url, task:"信息科技01"}
③ 教师端：发放 ──► guides.status = published（草稿学生看不见）
─────────────────── 以下是学生视角，零输入 ───────────────────
④ 学生登录学生端 ──► 点「今日 · 导学单 · 进入活动」
⑤ 浏览器打开 /g/<导学单id>/<条目序号>   ← 同源，带登录 Cookie
⑥ 服务端：验会话 → 查导学单 → 查条目 → 签一张票
          302 到条目真实地址，并把票和身份拼在 URL 上
⑦ 页面：读到 wbT 就知道「我是谁、交给谁」，登录浮层不出现
⑧ 每答一题 → POST /api/v2/student/submit?t=<票>
⑨ 服务端：验票 → 补学号/姓名/班级 → 转发到活动服务的 /api/<任务号>
⑩ 教师端「活动数据大屏」实时出现这个学生的这一题
```

---

## 4. 核心机关：闸门 + 票据

### 4.1 闸门 `/g/<gid>/<idx>`

学生端点条目时不再直接甩外链，而是先回工作台：

```
GET /g/12/3
  ├─ 没登录        → 302 /s/（回学生端登录）
  ├─ 不是本班的    → 提示页「找不到这份导学单」
  ├─ 还是草稿      → 提示页「老师还没发放」
  ├─ 条目没地址    → 提示页「这个环节还没有可打开的页面」
  └─ 正常          → 302 到条目地址 + 参数
```

成功时拼在 URL 上的参数：

| 参数 | 含义 | 谁用 |
|---|---|---|
| `wbT` | 票据（随机 27 字符，12 小时有效） | **提交时鉴权用** |
| `wbSid` / `wbName` / `wbCls` | 学号 / 姓名 / 班级 | 页面显示「已识别：七4班 · 周可欣」 |
| `wbTask` | 任务号 | 页面兜底/调试 |
| `wbBase` | 工作台地址 | 页面知道提交回哪 |
| `wbGid` | 导学单 id | 无票时向 `guide-ctx` 换票 |

### 4.2 票据里存什么

```python
{ sid, no, name, cls, gid, idx, task, exp }   # exp = 现在 + submit_hours（默认 12h）
```

票据**只存内存**，服务重启即失效——重启后学生重新点一次导学单就行，符合课堂节奏。

### 4.3 为什么不是「把学号写进 URL」

学号写在 URL 上，学生改一个数字就能冒充别人。票据不行：

- 票据是服务端签的随机串，猜不到；
- 票据里绑着 sid，改 URL 上的 `wbSid` 只是改显示，**提交时服务端只认票**；
- 票据过期就作废，不会长期飘在历史记录里。

## 5. 接口清单

| 方法 | 路径 | 鉴权 | 作用 |
|---|---|---|---|
| GET | `/g/<gid>/<idx>` | 学生会话 | 闸门：验身份 → 签票 → 302 |
| GET | `/api/v2/student/guide-ctx?gid=&idx=` | 学生会话 | 同源页面主动换票（页面被直接打开时的兜底） |
| POST | `/api/v2/student/submit?t=<票>` | 票 | 提交中转，身份由服务端补 |
| GET | `/api/v2/teacher/activity` | 教师会话 | 读当前配置 |
| POST | `/api/v2/teacher/activity` | 教师会话 | 保存 `api_base` / `submit_hours` |

### 提交中转做了什么

1. 验票（失败 → 401「提交凭证已失效，请回到学生端重新打开这一环节」）；
2. 读配置里的 `api_base`（没配 → 503「老师还没有在教师端配置活动数据服务地址」）；
3. 读原始 multipart 请求体，**在结束边界前插入三个字段**：`学号 / 姓名 / 班级`（值来自票据，不来自页面）；
4. 转发到 `api_base + /api/<task>`，把上游 JSON 原样回给页面；
5. 响应带 `Access-Control-Allow-Origin: *`——因为页面常常在另一个端口（5055）。

> 为什么不用「让活动服务开 CORS、页面直连」：
> 页面直连意味着地址要写进页面、身份要页面自己带，回到老问题。
> 中转还顺便解决了「学生手机到不了 QuickForm 容器、但能到工作台入口」的情况：
> 现在两者都在同一个网关后面（`/` 与 `/qf/`），中转变成后端内部调用。

## 6. 数据字段（导学单条目）

```jsonc
// guides.items[n]
{
  "type": "activity",            // material | activity | quiz | link | text | homework
  "title": "信息科技01",          // 学生端显示的条目名
  "url": "http://192.168.123.51:5055/submit/file.html?api=...&task=信息科技01",
  "task": "信息科技01",          // ★ 新增：大屏路由靠它
  "note": ""
}
```

`task` 是这次新增的字段，作用只有一个：**告诉服务端这一条的提交要进哪个大屏**。
新增条目的三条路径都会自动写入：

- 「一键模板生成」挂活动 → 自动写；
- 编辑器「从活动加入」→ 自动写；
- 手工填地址 → 从 URL 的 `?task=` 里自动解析。

## 7. 三种降级，学生都不会看到报错弹窗

| 情况 | 页面表现 |
|---|---|
| 有票（正常） | 顶部「已识别：七4班 · 周可欣」，答一题同步一题 |
| 只有 `api` 参数（老师发的老链接） | 退回直连模式，页面提示填学号（老行为，保留兼容） |
| 什么都没有 | 答题照常，状态显示「本地已存，等老师开放提交」，连上后可点「同步全部已答」补传 |

---

## 8. 教师端界面上的变化

- 「活动」页右上 *设置服务地址* → 除了存本地，**同时写进服务端配置**（换电脑、清缓存后自动恢复）；
- 导学单条目绑定活动后，`task` 自动带上，不需要老师再填一遍；
- 学生链接不再需要发给学生——学生从「今日」点进来即可（`/g/` 是内部路由，不外发）。

## 9. 验证记录（2026-11-01）

用真实 HTTP 走了一遍学生视角（不靠肉眼看界面）：

```
[200] 学生登录            周可欣 20250409 七4班
[302] /g/99001/0          Location 携带 wbT / wbSid / wbName / wbCls / wbBase / wbTask
[200] 提交（只带 答案+按钮+正确否）
                          mock 活动服务收到：学号=20250409 姓名=周可欣 班级=七4班
                                            按钮=第1题 单选 答案=B 正确否=正确
[401] 伪造票              提交凭证已失效
[302] 未登录访问闸门      → /s/
```

关键点：**页面一个身份字段都没传**，服务端补的三个字段与大屏要求的字段名完全一致。

## 10. 后续可做（未实现）

- 票据支持「续期」：学生关掉页面再打开不重新走闸门（现在重开就要重新点一次，成本很低）；
- 提交队列：断网时先把答案排队，恢复后按顺序补传（现在是「本地已存 + 手动补传」）；
- 大屏侧显示「已进入页面但未提交」的人数（需要闸门上报一次「进入」事件）。
