## 一、先把物理约束说清楚（历史前提，已不成立）

> **当时的前提：学生机不能访问互联网 → 学生机访问不到 NAS 上的服务端。**

网页必须有一个"能连上的地址"才会打开。当时判断 NAS 在远端、学生机连不上，
于是得出"学生端页面必须由教室里的那台电脑在局域网里提供"。

现在的前提是**师生机都能上网、且与 NAS 同处一个局域网**，所以这条约束不再成立：

```
学生机 / 教室电脑的浏览器  ──局域网 HTTP──▶  NAS 上的统一入口（gateway:8080）
                                              ├─ /      工作台（教师端 /teacher/、学生端 /s/）
                                              └─ /qf/   QuickForm
```

由此得出的角色划分：

| 角色 | 是什么 | 不是 |
|---|---|---|
| **服务端（NAS）** | 唯一主库：账号、班级、成绩、课件、提交记录；渲染教师端与学生端页面 | 不再由任何一台办公电脑兼任 |
| **教师端** | 浏览器里的一层网页界面（`/teacher/`） | 不是一个需要在本机常驻的进程 |
| **学生端** | 同一入口下的 `/s/` 网页 + 登录态 | 不依赖外网资源（字体/CDN/图标全部本地） |

> 当时的设想：**"教师端启动"= 启动本地服务 + 打开教师界面**，两件事绑在一次点击里。
> 现在是：在 NAS 上 `docker compose up -d` 一次起齐（gateway / workbench / quickform），
> 之后老师只开浏览器、打开固定入口即可。

## 二、六个真实场景（按一节课的时间线）

### 场景 1 · 上课前 3 分钟：确认服务在跑、把入口发下去

老师走进机房，打开浏览器进工作台。
期望：首页第一屏就有「**把这节课发给学生**」的入口（入口地址 + 二维码 + 一键复制）。

学生机那头：打开浏览器 → 输入/点击那个地址 → 学生登录页。

痛点（当时）：入口藏在"设置"里，且要老师自己去查 IP；学生机得手输一长串地址。

### 场景 2 · 打铃：谁来了、谁没来

学生陆续登录。老师需要一眼看到：**本班应到 N 人、已登录 M 人、谁没来**。
期望：座位表上直接体现（未登录的座位是灰的），不用去另一个"考勤页"。

现状：考勤是独立页面，老师要在座位表和考勤页之间来回切。

### 场景 3 · 讲课中：发这节课的任务

老师讲 10 分钟，然后要发"这节课的导学单"：3 个任务（看资料 → 做练习 → 提交作品）。
期望：一个动作发下去；学生端「今日」立刻出现这节课的任务卡；老师在教师端看得到**提交进度条**（几人已交 / 几人未交）。

现状：导学单在"导学单页"发、资料在"课件页"发、作业在"作业页"发——三个入口，老师每次都要想"这个该去哪发"。

### 场景 4 · 学生机断网了

某台学生机网线松了 / 交换机抽风。
期望：学生端页面仍然能用（所有静态资源本地化），恢复后数据自动补传；老师端能看到"这台机器掉线了"。

现状：`netsync.js` 有重试与坏行隔离，但没有"在线/离线"的可见提示。

### 场景 5 · 下课：考勤自动结算

整节课没登录的学生 → 自动记缺勤；上课 5 分钟后才登录 → 自动记迟到。
老师只需处理例外：把缺勤的改成病假/事假。
期望：座位表上方一张"今日考勤"卡，点数字就地筛选座位。

### 场景 6 · 课后 / 换班 / 换机器

- 课后：作业与作品批改、成绩录入、学习记录沉淀（学生端"我的"里能看到过往记录）。
- 换班：下节课另一个班，老师切班，学生端登录页的名单跟着变。
- 换机器：老师换教室/换电脑不用迁移任何数据——浏览器打开同一个入口即可；只有 NAS 迁移时才需要整体搬家（数据卷 + 加密备份）。

## 三、目标三端职责

### 服务端（NAS）

- 主库 + 版本号 + 墓碑；
- 跨设备一致（办公室电脑、家里电脑、手机看同一份数据）；
- 账号权威（教师账号、学生初始密码策略、密保）；
- 定时备份与归档；
- 同时渲染教师端与学生端页面（同一个入口）。

### 教师端（网页）

| 层 | 职责 |
|---|---|
| 服务 | `workbench` 容器提供 `/teacher/`、`/s/`、`/api/v2/*`；库与文件都在数据卷里 |
| 网页界面 | 老师的全部操作；**首页承担"开课"主线**（发入口 → 看签到 → 发任务 → 看进度） |

### 学生端（网页）

- 登录（选班级 → 选学号 → 密码）；
- 今日：这节课的内容 + 导学单 + 任务提交 + 签到状态；
- 我的：学号/班级/姓名、过往学习记录（作业、成绩、课堂表现、完成的活动）；
- 所有资源本地化，**零外网依赖**；
- 数据直接进出服务端，不存在"某台电脑先存一份再同步"的中间层。

## 四、界面重构要点（来自本次需求）

### 4.1 教师端顶栏

| 现在 | 改为 |
|---|---|
| 日期（可改成基准日期） + 全局班级选择器 + 搜索 + 系统设置 + 署名 | **只保留**：侧栏开关、全局搜索、（可选）当前班级小徽章 |
| 日期在顶栏 | 日期移到**问候语下方**："下午好，牛老师" / "11月1日 周日 · 第 10 周" |
| 设置入口在右上角 | 设置入口移到**左下角常驻**：头像 + 昵称，点开是账号信息 + 系统设置（主题、头像、昵称、问候语、数据导入导出） |

### 4.2 首页（"今天这节课"主线）

第一屏按老师的动作顺序排：

1. 问候 + 日期
2. **本节课卡**：第几节 / 什么课 / 哪个班 → 已登录 M/N → 「发学生入口」
3. 本节任务：导学单 / 下发资料 / 作业
4. 待办与提醒

### 4.3 学生端

- 登录页：现代化，大按钮、班级与学号用选择器；
- 今日：一张"这节课"主卡（课程名、老师、时间、签到状态）+ 任务列表（可展开、可提交）；
- 我的：个人信息卡（头像位、学号、班级、姓名）+ 学习记录时间线；
- 底部两个按钮加容器边框，选中态明确。

### 4.4 导航（保留 18 页，先不动结构）

本次只做壳层与首页，18 个功能页**保持现有布局**，逐页在后续迭代里重新设计。已知要动的三处（考勤并入座位表、导学单并入下发资料、课件页去掉"资料夹"）随对应页面一起改，不单独动刀。

## 六、待确认的一个技术边界

> **"教师端启动后自动拉起学生端网页入口"** —— 纯网页无法远程打开学生机上的浏览器（浏览器安全模型不允许）。

三条可行路径，效果差别很大：

| 方案 | 做法 | 老师要做什么 | 学生要做什么 |
|---|---|---|---|
| A 投屏 + 二维码（推荐起步） | 首页大卡片显示局域网地址 + 二维码 | 投屏 / 口头念一次 | 扫码或输 4 位短地址 |
| B 快捷方式分发 | 生成 `.url` 文件，随镜像/共享盘下发到学生机桌面 | 课前统一放一次 | 双击图标 |
| C 机房广播系统 | 借极域/联想/红蜘蛛等广播软件推送网址 | 用广播软件发一次 | 无 |

方案 A 现在就能做；B 只需要多生成一个文件；C 取决于机房装了什么。**需要老师确认机房有没有广播软件**——如果有，B/C 都能做到"学生机开机就进页面"。
