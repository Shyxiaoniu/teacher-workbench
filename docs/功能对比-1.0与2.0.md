# 班级工作台 1.0 → 2.0：功能对比与改进分析

> 对比基线 A：2026-10-26 推文《我不会写代码，但让 AI 给我写了 2.4 万行，做了个班级工作台自己用》所述 1.0（单 HTML 文件）
> 对比基线 B：本项目 2.0.38（2026-11-06），依据 `README.md` 与 `app/` 实际代码
> 说明：1.0 的源文件本机已不存在，1.0 侧能力均以推文原文为准；推文自述"15 个模块"，正文点名 14 个，另 1 个推测为首页/总览。

---

## 一、一句话结论

**1.0 是"一个老师在一台电脑上用的记录工具"，2.0 是"一个班在一间教室里一起用的教学系统"。**

功能不是"变多了"，而是**换了一个维度**：

- 1.0 解决"我记不住"——把纸质班务本搬进浏览器；
- 2.0 解决"我们不同步"——把老师、学生、课堂活动放进同一个数据源。

代价也很明确：部署从"双击一个文件"变成"要有一台常开的机器"，维护从"不用管"变成"要备份、要升级、要放行端口"。

## 二、形态与架构对比

| 维度 | 1.0（推文所述） | 2.0（代码实测） | 性质 |
|---|---|---|---|
| 交付形态 | 单个 `.html` 文件 | 服务端 + 教师端 + 学生端，46 个源码文件 | 重构 |
| 运行方式 | 双击浏览器打开 | 双击启动脚本（:20020）或 Docker（:8080） | 重构 |
| 数据存储 | 浏览器 localStorage | 服务端 SQLite，29 张表 | 重构 |
| 数据加密 | AES-256，密码不存明文，备份也是密文 | 服务端明文库 + 备份文件 AES 加密（`.cwbackup`） | 有取舍 |
| 使用人数 | 一台电脑、一个人 | 局域网内多教师账号（工作区隔离）+ 全班学生 | 质变 |
| 学生参与 | 无 | 学生端 `/s/`：签到、作业、资料、座位、测验、打字 | 新增 |
| 实时性 | 无 | SSE 推送 + 1.5 秒轮询兜底 | 新增 |
| 身份判定 | 单机密码锁 | 会话角色（教师/学生）+ 学生票据（12 小时，内存态） | 重构 |
| 时间源 | 本机浏览器时间 | 服务端时间为唯一时间源，两端只显示 | 新增 |
| 部署门槛 | 零 | 需要 Python 3.9+ 或 Docker、固定 IP、常开设备 | 上升 |
| 升级方式 | 换文件 | 在线更新（sha256 校验、失败回滚） | 新增 |
| 备份恢复 | 导出/导入浏览器密文 | 全量加密备份 + 两道导入拦截 + 每日快照 | 增强 |
| 代码规模 | 约 2.4 万行 | 约 6.7 万行（`app/` 下 py/js/html/css） | 2.8 倍 |
| 版本节奏 | 单文件迭代 | 2.0.1 → 2.0.38，逐次可追踪 | 工程化 |

**关键判断：** 数据加密从"浏览器端全密文"退到"服务端明文库 + 备份加密"，是 2.0 最大的取舍。

原因是多端并发：如果库是密文，服务端每次查询都要解密，实时同步、按班统计、字段投影全都做不了。补偿手段是：数据库文件放在自己的机器上、学生接口做字段裁剪、试卷答案不进同步快照、备份强制加密、部署到公网时要求自行加固。

对"数据绝不进浏览器以外的地方"的人来说，1.0 更纯粹；对"要多人多端用"的人来说，2.0 是唯一可行解。

## 三、推文 15 个模块逐项对比

| 12 | 待办 | 其他 · 待办 | **增强** | 今天/本周/全部、截止日、完成率、逾期提醒 |
| 13 | 工具箱 | 其他 · 工具 | **有增有删** | 保留点名/计时器/番茄钟/链接二维码；**删除截图工具**（局域网 http 下不可用） |
| 14 | 系统设置 | 顶栏 · 设置 | **增强** | 模块开关、密保、加密备份、在线更新、主题字号 |

**结构判断：** 1.0 的 15 个平级模块，在 2.0 被重组成 4 组 13 个入口（常用 3 / 教学 5 / 班务 2 / 其他 3）+ 顶栏设置。

合并的都是"低频、看一眼就走"的模块（德育、分组、值日、进度），它们被收进班级页的页签，左侧导航不再被撑长。教学类反而拆得更细（大屏、资料、作业、成绩、测验），因为每条都是独立工作流。

## 四、逐模块差异与改进点

### 4.1 座位表：从"排座工具"到"上课主界面"

| | 1.0 | 2.0 |
|---|---|---|
| 打开时机 | 排座、找学生时 | 每节课投屏常开 |
| 考勤 | 另开考勤页手点 | 座位格实时变绿，顶部按状态筛人 |
| 异常处理 | 无 | 病假/事假一键标记；强制考勤（🔒 锁定，签到不覆盖） |
| 收尾 | 无 | 「结算本节」落库 |
| 双端一致 | 无学生端 | 排座配置同步服务端，学生端读同一份 |

**改进点：** 把"考勤"从独立页签降维成座位表的一个状态层，老师不用在两个页面之间跳。这是 2.0 里体验提升最明显的一处。

### 4.2 考勤：从"N 次点击"到"0 次点击"

1.0 是老师判断、老师点。一个班五十来人，一节课点一遍，第三节就烦了。

2.0 的规则全部服务端化：

- 出勤：本节时间窗内登录（开始 5 分钟内）
- 迟到：超过 5 分钟
- 缺勤：15 分钟仍未登录且未请假，自动记录
- 请假：教师登记，优先级最高
- 强制：教师任意指定，学生签到不覆盖
- 时间窗：上一节下课 +1 分钟 ~ 本节下课；首节留课前 15 分钟；已下课不补签
- 课间：按"下一节有排课"归属，提前到机房不算迟到
- 防假全勤：本班该节没排课，不产生考勤

**改进点：** 老师从"操作者"变成"复核者"。默认全自动，只在异常时介入。

### 4.3 作业与成绩：从"记录"到"分析"

1.0：谁没交、多少分。
2.0：提交率趋势、批量催交、导出明细；成绩有及格率、优秀率、分数段、分析报告、班级/小组对比。

**新增闭环：** 测验页的成绩可以换算成百分制，一键写成一场考试，直接进入既有成绩分析——不用二次录入。

### 4.4 工具箱：删掉一个功能

截图工具在 2.0.32 被整体删除。

原因：`getDisplayMedia` 只在 `127.0.0.1` 或 `https` 下可用，老师在机房用局域网 IP 打开时点了就是"不支持"。一个大部分场景不可用的功能，维护成本高于价值。

同一批删掉的还有"学习单整页 HTML 存档"（2.0.35）：学生提交时克隆整页 DOM 存成 html，实际有用的只有学生交的文件。

**判断：** 这两处删除比很多新增更能说明 2.0 的成熟度——开始知道什么不该做。

## 五、2.0 新增的六类能力

### 5.1 学生端（`/s/`）

- 今日：一键签到、今日课程与学习单入口、待交作业、值日、座位卡
- 作业：本班作业与本人状态
- 课程：教师推送资料，在线预览
- 座位：全班座位表，自己高亮，讲台永远在上方（部分版本收在「今日」的座位卡里）
- 测验 / 打字：按教师开关动态出现

**边界：** 只下发"本班 + 本人"字段投影；座位表是唯一给同班姓名的接口，且不含电话、成绩、内部 id、考勤状态。

### 5.2 大屏与学习单

一条完整链路：

```
选课程 → 选学习单 → 按班下发 → 学生端出现入口
→ /g/act/<push_id> 验会话/班级/签到 → 签票 302
→ 提交 → 验票 → 用票内身份覆盖页面填写 → 落库 → 大屏实时
```

**设计要点：** 数据服务地址、任务号、学生身份都不出现在学生页面上；票只存内存、12 小时有效。

### 5.3 资料库与自动归档

- 目录即数据：`课件根/课程/子文件夹/文件`，不维护索引，拷走目录即备份
- 单文件 300MB，流式直传（浏览器 fetch body=File，服务端 256KB 分块）
- 网页可"设为学习单"，下发自动部署
- 学生提交即归档：`<课程>/<班级>/<学号-姓名>/<原名>`，同名不同内容加 `(2)`，永不覆盖

**改进点：** 归档从"前端在大屏刷新时顺带做"改成"服务端提交时做"，解决"学生说交了、资料里没有"的老问题。

### 5.4 测验 / 检测（2.0.38）

- 七种题型：单选、多选、填空、判断、连线、简答、图片上传
- 逐题分值/答案；按班发布；开放与截止时间；提交次数上限
- 两个开关独立：提交后是否显示答案、是否显示分数（服务端出网前裁剪）
- 判分：客观题服务端自动，主观题人工批阅，未批不显示 0 分
- 三处入口分工：大屏=收件看板，测验页=逐题与成绩分析，成绩页=百分制换算

### 5.5 打字冒险岛

六大篇章、每章每卷 10 关、BOSS 关、关卡内容随机、三星结算、指法高亮、8 只宠物、三类排行榜。教师一键开关，成绩服务端重算。

### 5.6 多教师、备份、在线更新

- 多教师账号 + 工作区隔离（`accounts/<id>/`），资料可复制共享
- 加密全量备份（29 表 + 配置 + 哈希 + 打字 + 附件），两道导入拦截
- 在线更新：24 小时检查、sha256 校验、失败回滚、数据原地保留

## 六、差异背后的三条主线

### 主线一：从"记录"到"协同"

1.0 的所有模块都是"我记下来"。2.0 有一半模块是"让他也知道"——学生知道作业、知道座位、知道学习单、知道自己的分。

这决定了架构必须从单机变多端。

### 主线二：从"前端状态"到"服务端权威"

| 事项 | 1.0 | 2.0 |
|---|---|---|
| 当前时间 | 浏览器 | 服务端 |
| 考勤判定 | 老师 | 服务端规则 |
| 成绩计算 | 前端 | 服务端重算 |
| 学生身份 | 无 | 票据 + 会话 |
| 数据一致性 | 单机无所谓 | rev 版本号 + SSE + 增量 |

实时系统里，"谁说了算"必须只有一个答案。2.0 选了服务端。

### 主线三：从"堆功能"到"治边界"

2.0 花在边界上的时间，比花在功能上多：

- 学生接口的字段投影
- 试卷答案的裁剪
- 关闭模块后接口 403
- 学习单票据的防冒名
- 归档路径的越权校验（commonpath）

功能漏了能补，边界漏了是事故。

## 八、2.0 仍然存在的短板

诚实列一下，免得读者装完失望。

1. **部署门槛上去了。** 要有一台常开的机器（NAS / 小主机 / 办公电脑），要固定 IP 或 DHCP 保留，要放行端口。1.0 的"双击就能用"没有了。
2. **运维责任在自己。** 备份、升级、磁盘、时区、证书，全要自己管。官方只提供工具，不提供托管。
3. **强依赖局域网质量。** 机房开 AP 隔离，学生就连不上；Wi-Fi 不稳，签到会卡。这是环境问题，软件解决不了。
4. **没有公网 SaaS 能力。** 外网访问要自己上 HTTPS / 反代；公网拉名单要班级码。想"发给家长一个链接就能看"——做不到。
5. **教师端移动体验弱于桌面。** 座位表、课表、大屏这些页面本质是桌面布局，手机上能用但不舒服。
6. **主观题必须人工批。** 简答、图片上传没有自动判分。
7. **没有家长端、没有校级多租户。** 一个实例服务一所学校的一个教师团队，跨校要各装各的。
8. **未做全校级压测。** 一个班 50 人、几个班并发的场景验证过；千人同时在线没有数据。
9. **迁移只能整库。** 没有"只导入某个班"的细粒度迁移。

## 九、适用建议

**适合上 2.0：**

- 有 NAS / 常开小主机 / 机房服务器
- 想要学生参与（签到、学习单、交作业、测验）
- 能接受每年花一两个小时做升级和备份
- 数据必须留在校内

**继续用 1.0 思路（单文件）更合适：**

- 只有一台办公电脑，没有常开设备
- 只想记录，不需要学生端
- 完全不想维护任何服务

**不建议用：**

- 没有固定网络环境、经常换教室
- 不愿做备份（单盘 NAS 且无备份 = 数据随时没）
- 需要家长端 / 校级统一管理
