## P-016 · 压缩包解压后「没有权限打开」

**版本**：2.0.16 ｜ **日期**：2026-11-05 ｜ **严重度**：高（阻断启动）

### 现象

- macOS / Linux 用户把发行包 `班级工作台<版本>-<yyMMdd>.zip` 解压后：
  - 双击 `启动工作台.command` → 系统弹「"启动工作台.command"没有权限打开」；
  - 或终端执行 `./启动工作台.command` → `Permission denied`；
  - 用 `ls -l` 看，`.command` / `.sh` 全是 `-rw-r--r--`（644），没有 `x` 位。
- 顶层启动器虽然能双击，但它 `exec` 的 `app/启动教师端.command` 同样报没有权限，
  所以还是起不来。
- Windows 解压不受影响（Windows 不认 Unix 权限位）。

### 触发条件 / 复现步骤

1. 在 **Windows 上**构建发行包（`python tools/make_release.py`）；
2. 把 zip 拷到 **macOS 或 Linux**，用系统解压 / `unzip` / `ditto` 展开；
3. 双击或执行包里任意 `.command` / `.sh` 文件。

> 只解压在 Windows 上打开，永远复现不了；Docker 部署也复现不了
> （Dockerfile 里有 `chmod +x /app/docker-entrypoint.sh`，compose 的 entrypoint
> 又走 `/bin/sh -c`，都不依赖 zip 里的权限位）。

### 原因分析

`tools/make_release.py` 构造 zip 条目时**只**写了权限，没写「这是 Unix 文件」：

```python
zi = zipfile.ZipInfo(path)
zi.external_attr = 0o100755 << 16      # ← 只写了这一半
```

`zipfile.ZipInfo.__init__` 会按平台设 `create_system`：**Windows 上是 0（FAT/MS-DOS）**，
Linux/macOS 上才是 3（Unix）。

而 ZIP 规范里，权限位（`external_attr` 高 16 位的 `st_mode`）只在
`create_system == 3` 时有意义。主流解压器看到 `create_system == 0` 会：

- 忽略高 16 位权限；
- 按 `umask` 给默认权限（普通文件 644）。

于是 `.command` / `.sh` 解压出来全是 644，没有执行位。

**为什么「修过一次还复发」**：早前确实补过 `external_attr = 0o100755 << 16`，
但没补 `create_system`，等于把权限写进了解压器不看的字段里。诊断证据（2.0.15 的包）：

```
条目 88 个｜目录条目 0 个｜文件 88 个
create_system 分布：{'FAT(0)': 88}
启动工作台.command                     mode=0o755 create_system=FAT(0) FAIL
app/启动教师端.command                 mode=0o755 create_system=FAT(0) FAIL
app/启动教师端.sh                      mode=0o755 create_system=FAT(0) FAIL
docker/entrypoint.sh                  mode=0o755 create_system=FAT(0) FAIL
```

模式位是对的，但 88 个条目「文件系统类型」全是 FAT —— 权限等于没写。

### 解决措施

1. `make_release.py` 新增 `_zipinfo(arcname, mode, mtime)` 统一构造条目：
   ```python
   zi = zipfile.ZipInfo(arcname, date_time=mtime or time.localtime()[:6])
   zi.create_system = 3                  # 3 = Unix，权限位才生效
   zi.external_attr = mode << 16         # 高 16 位 = st_mode
   zi.compress_type = zipfile.ZIP_DEFLATED
   ```
   所有条目（含 `发行说明.md`、`启动工作台.bat`、`启动工作台.command`）都走它。
2. 顺手把 `date_time` 设成源文件 mtime（原来不设，解压出来全是 1980-01-01）。
3. **新增构建后自检 `verify_release()`**：逐个条目检查
   - `create_system == 3`；
   - `.command` / `.sh` 为 755，其余 644；
   - 文件名带 UTF-8 标记（bit 11，否则中文乱码）。
   任何一条不合格 → **删除 zip 并让构建失败**，绝不产出坏包。

### 验证

- 重新构建后诊断：`create_system 分布：{'Unix(3)': 88}`，全部 PASS。
- 5 个可执行脚本（`启动工作台.command`、`app/启动教师端.command`、
  `app/启动教师端.sh`、`app/submission-system/run.command`、`docker/entrypoint.sh`）
  的 mode 均为 755，且 shebang 为 LF（无 CRLF）。
- `make_release.py` 若把 `create_system = 3` 去掉，构建会直接报
  「发行包自检失败（已删除产物）」并退非 0 —— 这就是防复发的闸门。

### 防复发

- 自检内建在构建流程里，不依赖人记得检查。
- 诊断脚本 `E:\wb-shots\run_zipperm.py`（计划任务 job `zipperm`）可随时复查任意包。

## P-015 · 自动更新并重启后服务起不来

**版本**：2.0.15 ｜ **日期**：2026-11-05 ｜ **严重度**：致命（服务全挂）

### 现象

教师端点「下载并安装」→「立即重启服务」后，页面一直转圈，最后提示服务没回来；
到服务器上看，进程已经不在了，手动再启动才恢复。

### 触发条件

Windows（或任何非 Unix）上通过教师端「立即重启」触发 `os.execv` 重启。

### 原因分析

Windows 的 `os.execv` 不是 Unix 那种「原地替换进程映像」，而是
**CreateProcess 起新进程 → 旧进程退出**，两者有一段并存窗口。

新进程启动时 `main()` 走 `PORTX.pick_port()`：

1. `is_free(port)` → 假（旧进程还在监听）；
2. `is_mine(port)` → 真（`/api/v2/ping` 返回 `service=workbench`）；
3. 返回 `state = "mine"` → `main()` 打印「已有一个本工作台实例在运行，不重复启动」并 **return**；
4. 旧进程随后也退出 → **服务彻底没了**。

### 解决措施

`/api/v2/update/restart` 在 `execv` 前：

1. `self.server.server_close()` —— 主动释放监听 socket，端口立刻空出来；
2. `os.environ["WB_RESTARTING"] = "1"` —— 给新进程留标记。

`main()` 里 `pop` 出 `restarting`：若仍判 `state == "mine"`，说明旧自己还没退干净，
等端口释放（最多 8 秒）后当作 `free` 继续启动；8 秒仍被占则保持 `mine` 退出
（说明旧进程根本没退，服务其实还在跑，绝不抢端口造两个实例）。

### 验证

- 重启前后 PID 变化：26484 → 14416；
- 旧会话失效（证明进程真的换过）；
- 服务 1 秒内恢复，版本不变；
- 另起一个实例仍被正确拦下（不会双实例抢端口）。

## P-014 · 教师端关掉签到，学生打开学习单仍被拦

**版本**：2.0.14 ｜ **日期**：2026-11-05 ｜ **严重度**：高（功能死锁）

### 现象

老师在设置里关闭「课堂签到」后，学生端今日页不再显示签到卡；但学生点学习单，
仍然弹出「请先签到 —— 今天还没有你的签到记录」，且没有任何入口可以签到。

### 原因分析

`_signed_today()` 只查考勤表当天有没有有效记录，**从不读 `CFG["checkin"]["enabled"]`**。
关闭签到 → 学生端隐藏签到卡（无法签到）→ 闸门却仍要求有记录 → 永久 403。

### 解决措施

`_signed_today()` 开头加：签到关闭即视为「没有签到要求」，直接返回 True。
学习单入口 `/g/act/<push_id>` 与资料入口 `/g/mat/<id>` 共用该函数，一处改两处生效。

### 验证

| 教师端状态 | 当天记录 | 打开学习单 |
|---|---|---|
| 无需签到 | 无 | 302 正常跳转 |
| 开启签到 | 无 | 403「请先签到」（照旧拦截） |

> 遗留：签到开关是全局配置，不是按教师账号。多教师场景下一位老师关闭会影响所有班；
> 目前两端判断标准一致不会死锁，若要做 per-teacher 需另立需求。

## P-013 · 检测得到更新，下载安装报 404

**版本**：2.0.13 ｜ **日期**：2026-11-05 ｜ **严重度**：高（无法更新）

### 原因分析

`version.json` 的 `zip` 只写了纯文件名，更新器把它拼到 manifest 所在目录（仓库根），
而包实际在 `dist/` 下。`check()` 只读 manifest、从不碰安装包，所以「检测永远成功、
安装永远 404」。

### 解决措施

- `make_release.py` / `version.json` 改写成相对仓库根的路径 `dist/<包名>.zip`；
- `updater._zip_urls()` 兼容三种写法并给出候选地址（完整 URL / 相对路径 / 老格式纯文件名），
  只有 404 才换下一个；全 404 时明确提示「安装包与 manifest 不一致」而不是笼统的地址错误。

## P-017 · 账号菜单里的设置项跳不到对应位置

**版本**：2.0.15 ｜ **日期**：2026-11-05 ｜ **严重度**：中

### 现象

左下角账号 → 菜单里点「主题与外观 / 字号 / 问候语 / 头像与昵称 / 数据导入导出」，
进入设置页后不管点哪个，都停在「外观与字号」这一屏。

### 原因分析

`settingsScrollTo()` 按 `#content .card` 的 `textContent.indexOf(关键字)` 找目标。
但「外观与字号 / 问候与好句 / 本地资料 / 数据与备份」**四个小节同属一张 `.card`**
（一个大 div 里用分隔线切开），所以四个关键字都命中同一张卡 → 只滚到这张卡的开头。

### 解决措施

- 五个小节标题挂 `data-set="theme|font|greet|nick|data"`；
- `settingsScrollTo` 优先 `querySelector('#content [data-set=...]')`，老布局才回落关键字；
- 滚动改手动算 `window.scrollTo`，偏移 = 顶栏实际高度 + 10
  （原来 `scrollIntoView(block:'start')` 会把标题压在 sticky 顶栏下）；
- 同页再点补 90ms / 320ms 两拍滚动。

### 验证

五个入口各自停在自己的小节，标题 top 70~71px（顶栏 60px），滚动位置 326 / 934 /
1106 / 1503 / 1924px，互不相同。

## P-018 · 每日一句右上角铅笔图标点击无响应

**版本**：2.0.15 ｜ **日期**：2026-11-05 ｜ **严重度**：中

### 现象

侧栏「每日一句」右上角的铅笔角标，鼠标点上去没有任何反应；
在设置页里点它更是完全无动静。

### 原因分析

`.gs-edit { pointer-events: none }` —— 点击穿透到整张 `.greet-side` 卡片上，
而整卡的 `onclick` 只做 `location.hash = '#settings'`：

- 不在设置页 → 跳过去，能滚到设置页顶部（看起来像「没弹编辑窗」）；
- 已在设置页 → hash 没变化，**浏览器什么都不做**（真正的「点了没反应」）。

### 解决措施

- `.gs-edit` 改 `pointer-events: auto` + `cursor: pointer` + 悬停底色；
- 角标自己 `event.stopPropagation()` 并直接 `openGreetSetting()` 弹浮窗；
- 补 `role="button"` + Enter/空格键支持；
- 整卡点击仍跳设置页（两个入口各司其职）。

### 验证

真实点击铅笔 → `#floatLayer` 出现且标题为「问候与好句设置」，
来源下拉、更换频率都在；已在设置页时点同样弹出。

## P-019 · 管理员「重置密码」弹窗界面空白

**版本**：2.0.17 ｜ **日期**：2026-11-05 ｜ **严重度**：中（功能可用但看不见）

### 现象

在 `/admin/` 点某个教师账号的「重置密码」，弹窗打开后**只剩标题栏和底部按钮**，
中间的说明文字和输入框是空白；换个浏览器 / 关掉插件后又正常。

### 触发条件

浏览器装了 uBlock Origin、AdBlock 一类广告拦截插件（默认规则集里含
`[class^="ad-"]`、`.ad-body` 这类泛化隐藏规则）。

### 原因分析

弹窗类名用了 `ad-*`：`.ad-ov / .ad-dlg / .ad-body / .ad-acts / .ad-btn / .ad-inp`。
广告拦截器的「元素隐藏」规则常按类名前缀或常见广告块名匹配，`.ad-body` 一旦被
`display:none`，卡片外壳（白底 + 圆角 + 阴影）和按钮都还在，**正文与输入框被藏起来**
—— 视觉上就是"一张空白弹窗"。

代码本身是正常的，已排除服务端与浏览器渲染问题：

- 隔离实例：DOM 里 title / bodyText / input 齐全，无 JS 报错；
- 正式服务：桌面 1440×900 与手机 390×844 两种视口，`.wbd`（当时还是 `.ad`）
  卡片 400px / 362px 宽，输入框可见，无报错。

所以根因定位在**类名触发广告拦截规则**，而不是逻辑缺陷。

### 解决措施

1. 类名统一 `ad-*` → `wbd-*`（workbench dialog），连 keyframes 一起改成
   `wbd-fade / wbd-in`；
2. **函数名保留** `adDialog / adPrompt / adConfirm / adToast` —— JS 标识符不受
   拦截规则影响，改名会让所有调用点失效；
3. `adDialog` 外层包 `try/catch`：极端环境（无 Promise / DOM 异常）降级到原生
   `prompt / confirm / alert`，不再出现「点了没反应」；
4. 正文为空时显示「（无更多说明）」，不再产出空白卡片；
5. `host()` 兜底 `document.body || document.documentElement`；
6. `/admin/` 底部显示当前版本号，用来判断浏览器是不是拿了缓存旧页。

### 验证

- 真浏览器复测外观参数全部不变：宽 400px、圆角 16px、标题 15px/600、
  按钮 gap 8px、主色 `rgb(15,110,86)`、危险色 `rgb(179,38,30)`、toast 距边 24px；
- 正式服务桌面 + 手机两种视口点「重置密码」均正常渲染。

### 防复发

- 新增 UI 类名前缀避开 `ad-` / `banner-` / `sponsor-` 这类广告拦截高敏感词，
  统一用项目自己的 `wbd-` / `wb-`；
- b17 的源码断言守住这条规则。

## P-020 · 学生端取不到班级 / 课程数据（教师端正常）

**版本**：诊断条目（未改运行逻辑） ｜ **日期**：2026-11-05 ｜ **严重度**：高

### 现象

教师端班级、课表、资料都正常；学生登录后页面空白或只有零星内容，
控制台没有明显报错。

### 两端的本质差异

两端**不是同一套查询**，只是同一份数据的不同出口：

| 维度 | 教师端 | 学生端 |
|---|---|---|
| 接口 | `/api/v2/sync?scope=teacher` | `/api/v2/sync?scope=student` |
| 取数 | `STORE.snapshot()` 全量 | 同一份快照，再过 `projection.project()` 裁剪 |
| 表数 | 29 张（**空表也下发 `[]`**） | 只下发有内容的表（`if picked:`，**空表整个 key 不出现**） |
| 行级 | 不过滤 | `classes` 只留 `id == student.class_id`；`students` 只留本人；`lessons/materials/homeworks/dutys/activity_pushes` 只留 `class_id == cls`；`scores/attendance` 只留本人 |
| 字段级 | 全字段 | 剔除家长电话、备注、教师内部字段 |
| 模块开关 | 不受限 | 老师关掉 作业/成绩/课件/德育/值日 → 整张表不下发 |
| 前置条件 | 只要登录 | 还要 `student_row(session.student_id)` 能找到学生 |

### 实测结论（2.0.17，隔离实例）

标准数据（班级 1/2、3 名学生、课程、课表、座位、资料、作业、成绩）：

- 教师视角 29 张表；学生视角 10 张表；
- **「教师有 / 学生没有」的表：无**；
- 行数差异只有 `classes 2→1`、`students 4→1`（正确的按班/按人裁剪）；
- `student/me`、`student/seatmap`、`student/now` 全部正常。

**当前代码在标准数据下两端都能拿到数据**。学生端空白不等于接口坏了，
绝大多数是「学生这一侧的归属或开关不满足」，被投影整行滤掉了。

### 已复现的失败形态（反例）

把一名学生的 `class_id` 置空后：

```
登录：{"ok": true, "name": "赵六", "checkin": null}          ← 登录照样成功
sync：ok=True 表={"courses":1, "periods":1, "students":1}    ← classes 消失
      lessons / materials / homeworks / scores / seats 全没
seatmap：{"ok": false, "msg": "没有对应的班级"}               ← 400
now：lesson 为空
```

**教师端这时完全正常** —— 因为教师端不按 `class_id` 过滤。
这就是「教师端有、学生端没有」最典型的现场。

### 现场数据体检（本机正式库）

`tools/diag_student.py` 结果：

```
default（主工作区）：班级 3 个（七1/七2/七4），学生 138 人
class_id 正常 138 人；缺失 0；指向不存在班级 0
账号 admin 工作区：空
== 数据体检：0 名学生归属异常 ==
```

本机数据是干净的，说明问题不在数据侧 —— 需按下面的步骤查环境/改动。

### 优先验证顺序（5 分钟内定位）

1. **先看接口，不看页面**：学生登录后 F12 → Network → 找
   `/api/v2/sync?since=0&scope=student`
   - `ok: false` → 看 `msg`（多半是「学生档案不存在」→ 工作区/账号绑定问题）
   - `ok: true` 但 `tables` 里没有 `classes` → 学生的 `class_id` 无效（见第 2 步）
   - `tables.classes` 有、但课程/资料空 → 检查老师是否关了「课件/作业/成绩」模块
2. **查库**：`python tools/diag_student.py --data <数据目录>`，看有没有
   `class_id 缺失 / 指向不存在的班级` 的学生
3. **查学生档案**：教师端「学生」页看该生的班级列是不是空的；或
   `/api/v2/student/me` 返回的 `class_id`
4. **查工作区**：多教师账号时，学生所在的教师账号和学生会话的 `account` 必须一致
   （不一致表现为 sync 直接 403，而不是空表）
5. **查模块开关**：教师端 设置 → 功能开关，确认作业/成绩/课件没被关掉

一条命令跑完 1~5 的接口部分：

```bash
python tools/diag_student.py --base http://<服务器>:8080 \
    --user teacher --pass <密码> --student <学号>
```

它会打印教师视角 / 学生视角各拿到哪些表、逐表行数对比，以及三个学生接口的
`ok/msg`。

### 改这些地方会引入什么新问题（风险点）

| 想改的地方 | 风险 |
|---|---|
| 放宽 `_keep()` 里 `classes` 的条件（cls=0 时放行全部） | **越权**：学生会看到别班的班级资料 / 座位 |
| 让 `_sync_pull` 在 class_id 无效时返回 `ok:false` | 前端 `pull()` 是 `if (!j.ok) return;`，会**继续静默**；若顺手改成 `location.reload()` 会变成**无限刷新** |
| 取消 `if picked:` 让空表也下发 | 前端对「表不存在」和「表为空」的处理不同，可能触发别的分支（`T('x')` 从 `undefined` 变 `[]`） |
| 用会话里的 `class_id` 代替学生档案的 `class_id` | 两者不一致时会把错误放大，且学生换班后会话不更新 |
| 登录时强制要求 class_id 有效 | 老数据里 `class_id` 为空的学生**全部登不进来**（现在至少能进去看到课程表） |
| 直接改库批量补 `class_id` | 补错班级 = 学生看到别班的资料和座位，属于数据泄露 |

**结论**：先定位是「数据归属」「工作区绑定」还是「模块开关」，再动代码。
不要为了让页面「有东西」而放宽投影规则。

### 已知的可观测性缺陷（建议改，但要单独验证）

`app/student/app.js` 的 `pull()`：

```js
if (!j.ok) return;                 // 失败静默
if (snapshot) S.loading = false;   // 只有成功才关 loading
```

后果：接口失败时页面**一直停在 loading**，学生和老师都看不到原因。
建议改成「失败也关 loading，并把 `j.msg` 显示出来」——只动 UI 分支，
不碰权限和投影。改完必须验证：401 仍走 `location.reload()`，
不会出现无限刷新。

## P-022 · macOS 更新后重启服务「没有权限」

**版本**：2.0.19 ｜ **日期**：2026-11-05 ｜ **严重度**：高（更新后起不来）

### 现象

在 Mac 上点「下载并安装」完成更新，之后重启服务起不来；双击 `启动工作台.command`
提示没有权限或被系统拒绝。

### 原因

更新器 `zipfile_guard()` 解压时用 `open(target, "wb")` 落盘 —— 文件的 Unix 权限位
被重置成 `0666 & ~umask`（通常 644），**zip 里存的 755 全部丢失**。换装后：

- `app/启动教师端.command`、`app/启动教师端.sh`、`app/submission-system/run.command`、
  `docker/entrypoint.sh` 全部变成 0644 → 不可执行；
- 顶层 `启动工作台.command` 不受影响（换装只动 `app/`），所以双击它能运行，
  但它 `exec` 的 `app/启动教师端.command` 会报「没有权限」。

> 和 P-016（打包时没写 `create_system`）是同一类问题的两个环节：
> **打包端**保证 zip 里有 755（2.0.16 已修），**解压端**还得把它还原到磁盘（本次修）。

### 解决措施

1. `updater.zipfile_guard()` 解压后按 `info.external_attr >> 16` 补 `os.chmod`；
   `mode == 0`（老包没写权限）时保持默认，不乱改。
2. `server.py` 新增 `_heal_exec_bits()`：每次启动检查这几个脚本有没有 `x` 位，
   没有就补 `|0o755`。**已经被旧版本更新坏的机器，升级到 2.0.19 后启动即自愈**。
   `main()` 与 `/api/v2/update/restart` 前都会调用。
3. Windows 上直接跳过（`os.name == "nt"`），不折腾权限位。

### 验证

b22 [D] 用 mock 记录 `os.chmod` 调用，解真实发行包后断言：

```
启动教师端.command   → 0o755
启动教师端.sh        → 0o755
run.command          → 0o755
entrypoint.sh        → 0o755
server.py            → 0o644
```

### 防复发

- 以后新增需要执行位的脚本，同时加进 `make_release.exec_rels` **和**
  `_heal_exec_bits` 的清单，两处都要。

## P-023 · 导入数据后学生端没有班级、登录不了

**版本**：2.0.19 ｜ **日期**：2026-11-05 ｜ **严重度**：致命（学生完全进不去）

### 现象

全量恢复数据后：教师端能看到班级、学生、课表，一切正常；学生端登录报
「没找到这个学生」，进去了也显示没有班级。

### 原因

`ACCOUNTS.restore()` 在「覆盖」策略下**整体替换 `teachers` 列表**：

```python
self.data = json.loads(json.dumps(data))   # teachers 被备份里的完全覆盖
self.data["admin"] = keep_admin            # 只保留本机管理员凭据
```

而备份里的 `teachers` 可能是：

- 2.0.12 之前的单账号版本 —— 那时根本没有 `teachers` 数组；
- 另一台机器 —— 账号 id 是 `t2` / `t3`，**没有 `default`**。

同时，**业务数据（班级 / 学生 / 成绩）一律落在 `default` 工作区**（导入时未登录，
`ACC.current_account()` 就是 `default`）。

于是出现错位：

| 谁 | 读哪个工作区 | 结果 |
|---|---|---|
| 教师端 | 他登录的那个账号（比如 `t2`，或 `default`） | 能看到数据 |
| 学生登录 | 遍历 `teacher_ids()` 找学生 | 列表里没有 `default` → **扫不到** → 「没找到这个学生」 |

`/api/v2/student/seatmap` 同样 `student_row()` 返回 None → 400「没有对应的班级」。

### 解决措施

`AccountStore` 新增 `_ensure_default_teacher()`，两处调用：

1. `__init__` 末尾 —— **启动自愈**，已经被导入搞乱的机器重启即修好；
2. `restore()` 之后 —— 边导入边补。

补回的是一个 builtin 的 `default`：密码留空（管理员可在 `/admin/` 重置），
用户名自动避让（`teacher` / `teacher2`…），不会顶掉已有账号。
原有的 `t2` 等账号原样保留。

### 验证

b22 [A] 构造「teachers 只有 t2、数据全在 default」的现场：

```

启动后 teachers = ["default", "t2"]        ← 自愈补回，t2 保留

学生视角表 {"classes": 1, "courses": 1, "lessons": 1, "students": 1}
座位表 ok=true
```

### 防复发

- 不要因为「教师端能看到数据」就认为数据是全的 —— 教师端和学生端读的是
  不同的工作区入口，见 P-020 的两端差异表；

## P-024 · 更新提醒：数字角标 → 底部提示条

**版本**：2.0.20 ｜ **日期**：2026-11-05 ｜ **严重度**：低（观感 / 可发现性）

### 现象 / 为什么改

新版本提醒原来有两个落点：**左下角头像上的红色数字角标** + **侧栏左下弹出的说明卡片**。

- 数字角标「1」跟未读消息长得一样，点开却不是消息；
- 卡片带两条更新说明 + 两个按钮，占掉侧栏左下角，跟迷你计时条
  （`.mini-bar`，`right:18px;bottom:18px`）抢位置；
- 关掉卡片后角标还留着，反而更像"有东西没处理"。

### 改成什么

**页面底部居中一条小提示**（`.upd-bar`）：

| 项 | 行为 |
|---|---|
| 文案 | `🚀 新版本 vX 可用，点此查看更新`（版本号用品牌色加粗） |
| 点击整条 | 跳 `#settings` 并把「软件更新」卡片滚到顶栏下方 |
| 键盘 | `role="button"` + `tabindex=0`，Enter / 空格同样跳转 |
| 关闭 | 右侧 ✕；写 `sessionStorage['wb-upd-bar-closed']=版本号`，本次会话不再弹 |
| 桌面 | 宽 520px 居中，距底 18px（含 `env(safe-area-inset-bottom)`） |
| 手机 | 通栏（左右 12px）、隐藏「查看」胶囊、文案可折行 |

旧的 `body.has-update` 伪元素角标、`.upd-mini` 卡片与 `updMiniIn` 动画已全部删除，
b23 有源码断言守着（`has-update` / `upd-mini` / `updMiniIn` 均不得出现）。

### 踩坑：整站 zoom 会把 fixed 元素一起放大（T-09）

第一版写 `width:520px`，实测 `getBoundingClientRect().width` 是 **603**，
手机上 367 → 溢出到 425。

排查过程（值得记住的方法）：

```
probe: rect=603, offsetWidth=520, clientWidth=518
       rectNoAnim=603（去掉动画和 transform 仍是 603）
```

`offsetWidth` 和 `rect.width` 不一致、且去掉 transform 后仍不一致 ——
说明**有祖先做了缩放**。`603 / 520 = 1.16`，正好是整站字号缩放的
`documentElement.style.zoom`。

**结论**：`zoom` 会同时放大 `position:fixed` 元素的布局尺寸和视觉尺寸，
`520px` 实际占 603 视觉像素。修法是在 JS 里按当前 zoom 反算：

```js
const Z = parseFloat(document.documentElement.style.zoom || '1') || 1;
bar.style.width = Math.round(520 / Z) + 'px';
bar.style.maxWidth = Math.round((window.innerWidth - 24) / Z) + 'px';
```

与 `syncSidebarHeight()` 里算 `--sb-h` 的思路一致（它用「视口高 ÷ zoom」）。
**以后凡是 fixed 定位的全宽/固定宽组件，都要按 zoom 反算。**

### 另外两个坑

1. **CSS `min()` 在这台 Edge 上不被解析**：`width:min(520px, calc(100vw - 20px))`
   整条声明被丢弃，宽度退回内容宽。改用 `width:520px; max-width:calc(100vw - 24px)`
   两条老写法，哪里都认。
2. **设置页末尾的卡片滚不到顶是正常的**：跳转后 `scrollY == maxScroll`（已经到底）
   但卡片 top 仍 232px —— 页面长度不够。断言应校验「已滚到底 + 卡片进入视口上半部」，
   而不是死抠 `top ≈ 顶栏高度`。

### 验证

b23：桌面 1440（宽 520、居中 460~980、距底 21）+ 手机 390（宽 367、居中 12~378、
不溢出）+ 点击跳转 + 滚到底 + ✕ 关闭后刷新不再弹 + 无 JS 报错。**0 失败**。

## P-025 · 本地数据导入「卡死」

**版本**：2.0.21 ｜ **日期**：2026-11-05 ｜ **严重度**：高（导入看起来永远完不成）

### 现象

教师端 设置 → 数据与备份 →「一键恢复」，选完文件、输完密码，界面直接定格：
转圈不动、按钮点不动、浏览器提示「页面无响应」，几十秒后才可能继续；备份越大越久，
大备份基本等不到结果，只能强杀。

### 卡在哪个环节：实测分工

把导入拆成四段分别计时（b24，真实规模数据）：

| 环节 | 实测 | 结论 |
|---|---|---|
| ① PBKDF2 派生密钥（15 万轮，纯 JS） | **1.1 秒** | 固定开销，可接受 |
| ② AES 解密 + HMAC 校验（纯 JS） | **0.54 MB/s** —— 2MB 3.7s、8MB 14.9s、20MB 约 37s | **就是它** |
| ③ `JSON.parse` + `apply()` 落本机 | 百毫秒级 | 不是瓶颈 |
| ④ 服务端 `/api/v2/admin/import` | **1345 行 0.15s、3703 行 0.38s** | **不是瓶颈** |

**根因**：②③ 都在浏览器主线程同步执行。②按 0.5MB/s 跑，20MB 的备份要 35 秒以上，
期间主线程被完全占满 —— 连 `busy('正在校验备份文件…')` 都来不及绘制，
所以用户看到的是"点完就死"。

**为什么不用 WebCrypto**：学校局域网是 `http://192.168.x.x`，**不是安全上下文**，
`crypto.subtle` 为 `undefined`，纯 JS 实现是唯一选择（cipher.js 头注释已写明）。

### 解决措施

`cipher.js` 新增 **`aesCbcDecryptAsync(key, iv, ct, onProgress, chunkBytes)`**：

- 按 **64KB** 分片（≈ 每片 120ms，低于可感知卡顿阈值），每片后 `setTimeout(step, 0)`
  让出主线程；
- 提供进度回调；算法与同步版逐字节一致（b25 对拍 7 组尺寸，含 1/2/3 块边界）。

`backup.js`：

- `decode(text, onProgress)` 内部加 `decBig()`，有 `env.decAsync` 就走分片版；
- `importFull()` 传回调 → 界面上滚动显示「正在解密备份 42%…」；
- **小的 ls 值仍走同步解密**（几 KB，没必要异步）。

### 验证

```
[1] 与同步版逐字节一致：0.001 / 0.05 / 0.3 / 1.2 MB + 1/2/3 块边界 全过
[2] 主线程：同步版 2MB 期间定时器触发 0 次（界面定格）
           分片版同期触发 32 次（界面活着），总耗时 3994 vs 3792 ms（+5%）
[3] 进度回调 33 次、单调递增、末值 1
[B] 服务端导入 1002 行 0.13 秒（确认不是瓶颈）
```

### 防复发

- **判断"是不是主线程被占死"的通用方法**：跑一个 `setInterval(…,16)` 计数器，
  操作期间计数几乎不涨 → 就是同步阻塞，不是网络慢、不是服务端慢；
- 以后任何"大文件 / 大 JSON 的纯 JS 处理"都要分片，单片控制在 ~100ms；
- 别去优化 `import_snapshot` —— 它是 0.1 秒级的，不是问题所在。

## P-026 · 打字岛「文章切换」后下方关卡不同步

**版本**：2.0.22 ｜ **日期**：2026-11-05 ｜ **严重度**：中（功能可用但显示矛盾）

### 现象

打字冒险岛 →「文章阅读」篇章，上方文章条写着《从百草园到三味书屋》并标注

   永远走自动轮换的池子。
3. **断点续打会串文章**：草稿只按 `sXcYlZ` 匹配，固定文章后进来还会问
   「继续上次的进度？」，而 `dr.text` 是**上一篇**的正文。

### 修法

| 位置 | 改动 |
|---|---|
| `boot()` | `S.art.id = readArtId();`（空 = 自动轮换，去掉 `TA.DEFAULT_ID` 兜底） |
| `viewMap()` | 有固定文章就 10 张卡都用它，否则才用 `TL.articleOf(ch, lv)` |
| `startLevel()` | 固定文章时 `dr = null`（不续用旧草稿） |
| `artBar()` | 固定态文案改「已固定，本卷 10 关都读这一篇」 |

### 验证（b26，演示模式真浏览器）

```

[2] 固定《散步》：条=散步，10 卡全部《散步》，按钮=换一篇
[3] 换《背影（节选）》：条和 10 卡全部更新，旧标题不残留
[4] 退回自动：条=自动轮换，10 卡恢复 10 篇
[5] 刷新：仍是《散步》，卡片仍是同一篇
```

### 已知限制（不在本次范围）

固定文章后，**10 关内容相同**（`genLevel` 对固定篇每关都返回整篇），
而成绩仍按「卷-关」记录 —— 所以换文章后第 1 关可能还显示上一篇文章的星级。
彻底解决需要把 `articleId` 纳入成绩 key（前端 `passed()`/`best`/草稿 +
服务端 `typing_store` 的记录键 + 排行榜），属于数据模型变更，需要单独立项。

## P-027 · 导入进度弹窗整体闪烁

**版本**：2.0.23 ｜ **严重度**：中（观感，像卡死）

### 原因

`backup.js` 的 `busy(msg)` 走的是 `E().toast(msg)`，而 `toast()` 的实现是：

```js
const old = $('.toast'); if (old) old.remove();
const d = document.createElement('div'); ... document.body.appendChild(d);
```

**每次调用都删旧节点、建新节点**。解密进度每 64KB 回调一次（8MB 备份 = 128 次），
于是整块提示反复销毁重建 —— 用户看到的就是持续闪烁/跳动，还会误以为卡死。

### 修法

新增专用进度卡 `.bk-prog`：

| 点 | 做法 |
|---|---|
| 节点 | **只建一次**，之后复用 |
| 文字 | 两个真正的 Text 节点，只改 `nodeValue`（连"替换文本节点"的 mutation 都没有） |
| 进度条 | 只改 `style.width`，带 `transition:width .18s linear` |
| 遮挡 | `pointer-events:none` |
| 宽度 | 按 `documentElement.style.zoom` 反算（T-09），手机不溢出 |
| 收尾 | `progressDone()` 淡出后移除；`fail()` 里也调用，避免盖在弹窗下 |

### 验证（b27，真浏览器 + MutationObserver）

```
连续更新 120 次：
  容器插入 1 次、移除 0 次、子元素重建 0 次
  同一节点 / 同一条进度条；宽度走到 100%；百分比同步
  pointer-events:none；淡入后 opacity=1
未知进度：走不确定态（扫光），不显示百分比；收尾能移除
手机 390：宽 358、左右留白、不溢出
```

### 防复发

- 长任务的进度**不要用 toast**，toast 的语义是"一次性消息"；
- 判断"有没有重建"最直接的办法：MutationObserver 数 `childList` 里的**元素节点**增删。

## P-023 补充二 · 「是不是多账号隔离导致的」——实测结论

**日期**：2026-11-23（b28）

### 结论：**不是隔离本身的问题，是账号表丢了 default 条目**

b28 构造了两个教师账号、两份独立工作区：

| 账号 | 工作区 | 数据 |
|---|---|---|
| default | `<DATA_DIR>/workbench.db` | 七1班 / 学生甲 |
| t2 | `<DATA_DIR>/accounts/t2/workbench.db` | 七2班 / 学生乙 |

实测：

```
学生甲（default）登录成功 → 班级=['1']，看不到 id=2 的班（隔离生效）
学生乙（t2）登录成功     → 班级=['2']，看不到 id=1 的班（反向隔离也生效）
```

**说明多账号隔离本身工作正常**：学生登录会遍历 `teacher_ids()` 找自己，找到后
会话绑定到那个工作区，之后的名单/资料/成绩都只在那一份里 —— 这正是设计意图。

真正的坑在 **`ACCOUNTS.restore()`**：它整体替换 `teachers` 列表，而备份可能来自
旧版本（没有 teachers 数组）或另一台机器（id 是 t2/t3）。列表里没有 `default`，
但业务数据全在 default 工作区 —— 于是学生登录扫不到自己。2.0.19 加了启动自愈
（`_ensure_default_teacher`），b28 [C] 验证：

```
手工删掉 default → teachers=['t2']
启动后            → teachers=['default','t2']，学生甲依然能登录，依然只看到本班
```

### 怎么快速判断你遇到的是哪一种

```bash
python tools/diag_student.py --base http://<服务器>:8080 \
    --user teacher --pass <密码> --student <学号>
```

- 「数据体检」列出 `class_id` 为空 / 指向已删班级的学生 → **归属问题**；
- 接口对比里学生视角 `tables` 没有 `classes` → 同上；
- 学生直接 403「学生档案不存在」→ **工作区/账号表问题**（看 accounts.json 的 teachers）；
- `tables` 有 `classes` 但没有 `materials/homeworks` → **模块开关被关**，不是隔离问题。

## P-030 · 学生端站内跳转开新标签，返回错乱

> **后续（2.0.30，见 P-039）**：牛哥最终确定「网页都要在新标签独立打开、学生端不关闭」，
> 本条的「站内改同标签」已被撤销。P-030 里「越点越多」的问题改用**同地址复用标签**
> （`_wbTabs` + `focus`）解决，而不是把学生端顶掉。

**版本**：2.0.24 ｜ **严重度**：中（导航体验）

### 现象

学生端点资料「打开」、点站内任何链接，都会弹出新标签；在那边点返回，浏览器回到的
还是旧标签里的学生端 —— 看起来像"点一次多一个页面"，学生也以为数据丢了。

### 原因（代码位置）

`app/student/app.js`：

1. **`openNewTab(url)`（约 48 行）**：无条件 `window.open(url, '_blank')`，
   注释写着"所有「离开当前页」的跳转一律开新标签页（2026-11-05 牛哥要求）"。
2. **全局 `a[href]` 兜底监听（约 1713 行）**：页面上任何链接都 `preventDefault()`
   后转给 `openNewTab()` —— 本意是"以后新加的链接不用逐个写 target"，
   结果连站内页面也一起被推到新标签。
3. 受影响的调用点主要是资料页 `openMatSheet()` 里的
   `openNewTab('/g/mat/' + id)`（网页 / `.url` 资源点击即开）。

当时的初衷是"别把学生端顶掉、回来要重新找位置"；但对**站内页面**这是过度反应，
新标签与旧标签的会话、滚动位置各自独立，反而更乱。

### 改法

`openNewTab()` 内部按目标分流，**函数名与调用点都不动**（调用点多，改名只增加风险）：

```js
function isSameSite(url) {
  try { return new URL(url, location.href).origin === location.origin; }
  catch (e) { return true; }        // 解析不了就当站内，宁可同标签
}
function openNewTab(url) {
  if (isSameSite(url)) { location.href = url; return true; }   // 站内：当前标签
  var w = window.open(url, '_blank');                          // 外链：仍新标签
  ...
}
```

- 全局 `a[href]` 监听的逻辑**不变**（仍统一转给 `openNewTab`），所以以后新加的
  链接自动按同一规则走；
- **例外（刻意保留）**：预览弹窗里的「下载原文件 / 在新窗口打开」指向
  `/cw/<id>` 文件而不是页面，「在新窗口」是明确的操作意图，保持 `target="_blank"`。

### 验证（b29）

```
站内 <a href="/s/?probe=1">  → 标签页 1 → 1，当前标签 URL 已变
站内 /g/mat/999999           → 标签页 1 → 1
外部 https://example.com     → 标签页 1 → 2，原标签仍是学生端
无 JS 报错
```

## P-031 · 学习单身份信息重复显示两条

**版本**：2.0.25 ｜ **严重度**：低（观感）

### 现象

学生端打开学习单：左上角一条「已识别：七1班 · 肖泽楷（20250108）」，标题下方还有
模板自带的「👤 七1班 · 肖泽楷（20250108）」，两条并排。

### 原因（代码位置）

`app/index.html` 的 `actBuildCustomPage()` —— 学习单页面的**注入逻辑唯一实现**
（老师在教师端点「下发」时跑一次，注入结果存进 `custom_templates`，学生端只是加载）。

注入的运行时里：

```js
if (WB_SID) {
  ...
  var hi = document.getElementById("actHi");
  if (hi) { hi.textContent = "已识别：…"; }
  else { var d = …; d.id = "actHi"; document.body.insertBefore(d, document.body.firstChild); }
}
```

**无条件往 body 最前面插一条**。而不少学习单模板自己就画了身份胶囊
（模板里的 JS 会把 `${cls} · ${name}（${sid}）` 填进去），于是出现两条。

### 改法

插入前先扫页面：

```js
var _own = false;
for (每个叶子节点 e in body.querySelectorAll('*')) {
  if (e.id === 'actHi') continue;          // 我们自己那条不算
  var t = (e.textContent || '').trim();
  if (!t || t.length > 80) continue;        // 长段落不算，避免误判
  if (t.indexOf(学号) >= 0 || t.indexOf(姓名) >= 0) { _own = true; break; }
}
...
else if (!_own) { 才插入 #actHi }
```

- 模板已有身份 → **不插**，保留模板那条（牛哥要删的就是平台这条）；
- 模板没有 → 仍补 `已识别：…`，学生知道自己的身份（保底）；
- 原有 `#actHi` 存在时仍只更新文字，不重复创建。

## P-032 · 换设备导入后学生端「没有创建班级」

**版本**：2.0.26 ｜ **严重度**：致命（学生进不去）

### 现象

新版本导出 → 换一台设备导入 → 教师端登录后班级、学生、课表都在，
但**学生端登录页显示「没有创建班级」**，学生选不了班。

### 原因

登录页的班级下拉来自 `/api/v2/public/classes`（`_public_classes`），它用的是

```python
STORE.table_rows("classes")     # STORE = 按当前请求绑定的账号取库
```

未登录时 `_bind_account` 把账号设成 `default` —— **只查 default 工作区**。

而全量恢复是按**当前账号**写回工作区的。如果这台设备上教师使用的是 `t2`
（或恢复时落在 t2），班级数据就在 `<DATA>/accounts/t2/workbench.db` 里：

| 谁 | 查哪个工作区 | 结果 |
|---|---|---|
| 教师端（登录 t2） | `accounts/t2/` | 看得到班级 ✅ |
| 登录页（未登录） | `default`（空） | **空列表** ❌ |

> 2.0.19 的 `_ensure_default_teacher` 只保证「default 这个教师账号存在」，
> 补出来的是**空工作区** —— 正好绕过了这个盲点，所以升级了也没好。

### 改法

1. `_public_classes()`：遍历 **所有教师账号**合并班级，id 写成 `账号|班级id`
   复合键（不同账号可能有同 id 的班，不加前缀会串）；
2. `_public_students()`：用 `_split_acc_id()` 拆前缀，只查那个账号；
3. `/api/v2/auth/student`：同样拆前缀 —— 带前缀只查指定账号，
   **不带前缀仍按老逻辑全账号遍历**（老页面、老缓存兼容）；
4. 单账号场景 id 也会变成 `default|1`，服务端能拆，登录不受影响。

### 验证（b31）

```
default 留空、班级只在 t2：
  /public/classes → [{"id":"t2|2","name":"七2班","acc":"t2"}]
  /public/students?class_id=t2|2 → [学生乙]
  auth/student(class_id="t2|2") → ok，登录后能拿到本班数据
  auth/student(class_id="2")    → ok（老格式兼容）
两个账号都有班级 → ["七1班","七2班"] 都列出来
```

### 怎么自助确认

```bash
python tools/diag_student.py --data <数据目录>
```

会列出每个工作区各有几个班、几名学生。**如果 default 是 0 个班而 `accounts/xxx`
里有班**，就是这个问题（2.0.26 已修）。

## P-033 · 大屏：一条问卷提交显示成两条 + 缺正确率

**版本**：2.0.27 ｜ **严重度**：中（统计不可信）

### 一、一条提交显示两条

**代码位置**：`app/index.html` 的 `actTaskWindowsHtml()`。

```js
const btns = Array.isArray(lay.buttons) ? lay.buttons.slice() : [];
rows.forEach(s => { const b = actTaskOf(s); if (b && btns.indexOf(b) < 0) btns.push(b); });
```

**用原始字符串做 `indexOf` 去重**。老 layout 里可能同时存在「提交任务一」和
「提交任务一 」（尾空格 / 双空格），两个变体都被当成独立按钮 →
**同一份提交在两个窗口里各渲染一次**，看起来就是"一条数据出现两次"。

**改法**：按钮名归一化（`trim` + 把连续空白折成一个空格）后再去重，过滤时也用归一化值比。

**验证**（b32）：`buttons: ['提交任务一','提交任务一 ','提交任务二']` + 4 条提交 →
只渲染 **2 个窗口**（修复前是 3 个）。

### 二、逐题正确率与整体分布

**数据来源**

| 层 | 说明 |
|---|---|
| 作答记录 | 每次点提交按钮，前端 `actSubmitBlock()` 把该块内的 `input[name]` 收成 FormData 发到 `/api/act/<task>`，一条记录一行 |
| 正确答案 | **下发时**由 `actScanLayout()` 扫出来存进 `config.json` 的 `custom_layout[task].questions[].answer` |
| 题目结构 | 同一次扫描记录 `{btn, title, kind, name, multiple, options, answer}` |

**正确答案的三种标注方式**（模板任选其一，扫不到就只出选项分布）：

1. 题目容器：`<div class="act-q" data-answer="B">`（多选 `data-answer="A,C"`）
2. 选项：`<input type="radio" name="q1" value="B" data-correct="1">`
3. 选项或它的 `label`：`class="correct"`

**统计口径**

- 逐题：`正确人数 / 作答人数`，分母是**实际选了这项的人**（没作答不计入）；
- 多选：选中的集合与答案集合**完全相等**才算对；
- 整体：参与人数、平均正确率（各题正确率的算术平均）、
  答对题数分布（按 学号→答对题数 累计，没有学号退回姓名）。

**展示形式**（大屏每个收集窗口内）

```
第1题 语音识别的第一步        32 人作答 · 正确 28/32 · 88%
  A ████████████  28 · 88%  ✓
  B ██             3 · 9%
  C                1 · 3%

整体答题情况                  共 3 道有答案的题
[参与人数 32] [平均正确率 76%] [逐题均值 76%]
对 3 题 12 人 · 对 2 题 15 人 · 对 1 题 5 人
```

**刷新方式**

- 主通道：SSE（`/api/v2/events`），学生提交后服务端 `notify()`，大屏收到 `rev` 事件重绘；
- 兜底：EventSource 断开时 12 秒轮询一次 `act-data`；
- 数据本身不缓存（`cache:"no-store"`），重绘即最新。

### 防复发

- 凡是**用字符串当 key** 的地方（按钮名、班级名、题目标题），先归一化再比较；
- 加了「正确率」这类派生指标，必须明确**分母**是什么，以及没答案时怎么显示（宁可不显示，也不谎报 0%）。

## P-039 · 学生端网页被改成同标签打开，回不到学生端

**版本**：2.0.30 ｜ **严重度**：中（导航体验）

### 现象

学生点开学习单/资料网页后，学生端被顶掉；看完要按浏览器返回，回来位置丢了，
想同时看另一份资料就得反复前进后退。

### 背景

这是 2.0.24（P-030）改动的反向修正：

| 版本 | 行为 | 结果 |
|---|---|---|
| 2.0.23 及以前 | 一律 `window.open(_blank)` | 原页留着，但同一份资料点两次会开两个标签 |
| 2.0.24 ~ 2.0.29 | 站内 `location.href` 同标签、站外新标签 | 学生端被顶掉，回不到原位置 |
| **2.0.30** | **一律新标签 + 同地址复用** | 原页留着，也不越点越多 |

### 改法（`app/student/app.js`）

```js
var _wbTabs = {};                    // 绝对地址 → window
function openNewTab(url) {
  var abs = new URL(url, location.href).href;
  var old = _wbTabs[abs];
  if (old && !old.closed) { old.focus(); return true; }   // 同地址：切回去
  var w = window.open(abs, '_blank');
  if (!w) { toast('浏览器拦住了新标签页…'); return false; } // 绝不 location.href 兜底
  w.opener = null;
  _wbTabs[abs] = w;
  return true;
}
```

- `openMatSheet()`（资料「打开」）与全局 `a[href]` 兜底都走它，入口只有一处；
- `#锚点` / `javascript:` / `download` / 已显式写 `target` 的链接不拦；
- 弹窗被拦时只提示，不用 `location.href` 兜底 —— 那会把学生端顶掉。

### 验证（b35）

```
站内网页：1 → 2 个标签，学生端 URL 未变
同一地址再点：仍 2 个（focus 已有标签，原标签未关闭）
外链：2 → 3；页内 #锚点：不新开；显式 target=_blank：只开一个
学生端导航仍在、无 JS 报错
源码：isSameSite 已移除、openNewTab 无 location.href、_wbTabs + focus 就位
```

## P-040 · 导入名单弹窗「确认导入」要滚到底才能点

| 提示 | footer 里加 `#clsImpFootHint`，`clsRecomputeDup()` 时写「共 N 人 / 有学号重复」 |

## P-036 · macOS 更新后重启失败，弹「选择端口号」

**版本**：2.0.28 ｜ **严重度**：致命（更新后服务起不来）

### 现象

Mac 上点「立即重启」后，弹出「班级工作台 · 端口设置」窗口；选了新端口，
服务仍起不来，浏览器打开老地址一直转圈。反复重开也一样。

### 原因链

1. 重启走 `server.py` 的 `/api/v2/update/restart` → `server_close()` → `os.execv`；
2. 旧进程关掉监听后，浏览器那边的 SSE / keep-alive 连接让端口短暂 TIME_WAIT；
3. 新进程 `main()` 调 `pick_port()`，第一步 `is_free()` **故意不带 SO_REUSEADDR**
   （防止 Windows 上 bind 到别人端口）→ TIME_WAIT 被判成「不可用」；
4. `is_mine()` 此刻 ping 不通（新进程还没监听）→ 不是「自己的实例」；
5. `no_dialog` 默认 False → **弹出 Tk 端口窗**；用户选了新端口，配置被改写，
   服务起在 20021，而书签/桌面图标还指着 20020 → 「怎么都起不来」。

### 改法

| 位置 | 改动 |
|---|---|
| `core/ports.py` | 新增 `can_bind()`（带 SO_REUSEADDR，问「服务端现在能不能绑」）与 `_conn_refused()`（select + SO_ERROR） |
| `core/ports.py` | `pick_port(..., reuse_ok=True)`：`is_free` 假、`can_bind` 真 → 判定「旧连接收尾中」，留在原端口 |
| `server.py` | 重启时先等 20 秒让端口可绑；`no_dialog=args.no_dialog or restarting`；`trust_own=restarting` |
| `launch.py` | 子进程加 `--no-dialog`，端口只由启动器负责 |

### 边界

`can_bind(trust=True)` 只给「刚放开自己端口」的重启用：Windows 关掉监听后端口会挂起，
新 SYN 被丢弃，和「别人 backlog 满」无法区分；普通启动仍走严格判定，绝不抢别人的端口。

### 验证（b33）

```
监听中：can_bind=False / is_free=False
关闭后：trust=True（重启能立刻绑回原端口；strict 在 Windows 仍为 False，正说明必须 trust）
pick_port(reuse_ok+trust_own)：留在原端口；can_bind 假时仍判 busy
源码：no_dialog=args.no_dialog or restarting / trust_own=restarting / 子进程 --no-dialog
```
