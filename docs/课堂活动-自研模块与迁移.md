# 课堂活动：自研模块与 QuickForm 迁移

> 版本：班级工作台 2.0 · 2026-11-03
> 对应代码：`app/activity.py`（数据层）、`app/server.py`（接口/兼容层）、
> `tools/migrate_qf.py`（迁移 CLI）、`app/index.html`（活动管理面板）

## 一、为什么要自研（方案 B）

QuickForm 在本项目里只承担了两件事：**存活动与提交、给个后台管理界面**。
身份（学号/姓名/班级）、鉴权（签名票）、活动发放、数据大屏、课件归档、
备份，本来就都是工作台自己做的——`quickform/serve.py` 甚至专门加了三个
内部端点让工作台绕过 QF 登录直接读写它的库。

更关键的是数据模型：**QuickForm 不认识「班级」和「学号」**，这些是工作台
在提交时以中文字段名塞进 JSON 的，于是「按班统计提交率」「缺交名单」
只能在前端拼 JSON，既慢又不准。

自研后：活动/提交/附件进工作台自己的库，提交表里直接有 `sid / name / cls` 列。
同时少一个容器、少一套账号、少一层 `/qf` 前缀适配。

## 二、数据落在哪

| 内容 | 位置 |
|---|---|
| 活动（act_task） | `<数据目录>/workbench.db` |
| 提交（act_submission） | 同上，`data` 列存原始 JSON，`sid/name/cls/ip` 单独成列 |
| 附件记录（act_file） | 同上 |
| 附件文件 | `<数据目录>/activity/<活动号>/<12位随机名>.<ext>` |
| 对外 URL | `/static/uploads/<活动号>/<文件名>`（**与 QuickForm 时代完全一致**） |

> 备份口径已合一：全量备份（`full=1`）里多了 `activity` 段
> （tasks / submissions / 附件 base64），不再需要单独打包 QF 数据卷。

## 三、接口（与 QuickForm 同构）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/qf/api/tasks` | `{success:true, tasks:[{task_id,title,api,count}]}` |
| GET | `/qf/api/<task>` · `/all` | 全部提交（含 `_submission_id`、`submitted_at`） |
| GET | `/qf/api/<task>/count` | `{total_submissions}` |
| POST | `/qf/api/<task>` | 匿名提交（老师自建页面直连用） |
| GET/POST | `/qf/_wb_internal/list|clear|delete` | 数据大屏读/清空/删单条（须教师登录） |
| GET | `/static/uploads/<task>/<file>` | 附件（图片/PDF/音视频内联，其余强制下载） |

教师端专用：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v2/teacher/activity/list` | 活动列表 + 提交数 + 资料附件 |
| GET | `/api/v2/teacher/activity/data?task=` | 单活动全部提交 |
| GET | `/api/v2/teacher/activity/export?task=&format=csv|json` | 导出（CSV 带 BOM） |
| POST | `/api/v2/teacher/activity/save` | 新建 / 修改（带 task_id 即修改） |
| POST | `/api/v2/teacher/activity/delete` | 删活动（连带提交、附件、发放记录） |
| POST | `/api/v2/teacher/activity/clear` | 清空提交 |
| POST | `/api/v2/teacher/activity/del-sub` | 删单条提交 |
| POST | `/api/v2/teacher/activity/upload?task=` | 上传教学资料（multipart，单文件 40MB） |
| POST | `/api/v2/teacher/activity/migrate` | 导入旧 QuickForm 数据（默认预演） |

学生提交仍走 `POST /api/v2/student/submit?t=<票>`：身份由服务端从票里取，
页面自己填的学号会被覆盖（防冒名）。后端为内置时**不再要求配置「活动数据服务地址」**。

## 四、切换与回退

```bash
# 默认：内置（不需要任何额外配置）
WB_ACTIVITY_BACKEND=builtin

# 临时回退到旧 QuickForm 容器（需自行把 quickform 服务与数据卷挂回来）
WB_ACTIVITY_BACKEND=qf
```

优先级：环境变量 > 教师端配置 `activity.backend` > 默认 `builtin`。
前端启动时会读 `/api/v2/state` 的 `activity_backend`，据此决定 `qfApiBase()`
走同源 `/qf` 还是历史保存的外部地址。

## 五、迁移旧数据

```bash
# 预演（只看数量，不写库）
python tools/migrate_qf.py

# 真正写入
python tools/migrate_qf.py --apply

# 活动已存在且要重导（先清空该活动的提交）
python tools/migrate_qf.py --apply --replace
```

也可以不敲命令：教师端「上课」→ **⚙ 活动管理** → **导入旧 QuickForm 数据**，
先预演再确认写入。迁移会做三件事：

1. 按原 `task_id` 建活动（11 位号保持不变，旧链接继续有效）；
2. 提交原样搬入，学号/姓名/班级/_ip 抽成列；
3. 把 `attachment` 指向的文件从 QF 的 `static/uploads/<task>/` 复制过来，
   并把 JSON 里的 URL 改成本地同构路径。

导完会逐活动比对条数，不一致直接报错（不会静默少数据）。

## 六、已知边界

- **不做多用户/角色**：教师身份就是工作台的教师会话，学生身份就是票。
  QuickForm 的「用户管理 / 所有者校验」不再需要。
- **不做 AI 分析、图表报告、二维码、模板导入导出**：这些是 QuickForm 的
  附加功能，实际课堂没用上；需要时在工作台里另做（数据已经能直接查）。
- **附件上限**：单文件 40MB、整份提交 40MB（与原来一致）；备份打包时
  单文件 >10MB 或合计 >40MB 会跳过并点名，不静默丢。
- **`quickform/` 目录保留**：作为回退源码。删掉它之前，不能删
  `THIRD-PARTY-NOTICES.md` 里的 MIT 声明与 `quickform/app/LICENSE`。
