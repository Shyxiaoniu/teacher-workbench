## 三、缺陷清单

### F1（高危）导入空 / 缺表的备份会清空全部数据，并提示成功

- **位置**：`app/server.py` `_import()` → `app/core/store.py` `import_snapshot(tables, replace=True)`
- **复现**：
  ```
  POST /api/v2/admin/import   {"tables": {}}
  → 200 {"ok": true, "counts": {}}
  → 之后导出：classes = 0，全部业务数据消失
  ```
- **原因**：`replace=True` 先把所有存活行打成墓碑，再按 `tables` 逐表写回。
  `tables` 为空（或缺少某张表）时，等于"只删不写"，且没有任何前置校验或事后告警。
- **触发面**：
  1. 手工编辑过的 `.json` 明文备份；
  2. 旧版本客户端 / 第三方脚本调用该接口时漏传表；
  3. 用**旧版本备份**导入新版本（备份中不存在的新表会被清空）——这一条在真实换机中相当常见。
- **影响**：一次性丢掉全部班级、学生、成绩、考勤数据，且界面提示"恢复成功"。
- **建议**：
  - 导入前校验：`tables` 为空直接 400；总行数为 0 一律拒绝；
  - 增加"下限保护"：备份总行数 < 当前数据 10% 时要求显式 `force=true` 才执行；
  - 导入前后各打一次快照，返回 `before/after` 行数供前端提示；
  - 前端在确认框里显示"本次将删除 N 行、写入 M 行"。

### F2（中）学生口令表"只增不清"，与"整体替换"的承诺不符

- **位置**：`app/core/store.py` `import_creds()`（第 720 行）
- **现象**：目标设备原有 `stale-s` 的密码哈希，导入后依然存在（3 条 vs 备份 2 条）。
- **原因**：`import_creds` 只做 `set_cred` 循环，没有先清空不在备份中的记录。
- **影响**：孤儿口令长期堆积；导出再导入会把它们继续传播；若将来学生 id 复用会造成串号。
- **建议**：导入事务内 `DELETE FROM student_creds WHERE student_id NOT IN (...)`，与表数据保持一致语义。

### F3（中）打字练习数据不在备份内

- **位置**：`app/core/typing_store.py`（独立文件 `DATA_DIR/typing.json`，不进 29 表体系）；`_export` 只取 `STORE.snapshot()`
- **影响**：换机后打字练习的正确率、金币、装扮、周榜全部归零，学生会认为"白练了"。
- **建议**：把 `typing.json` 放进 `sub` 同级的新段（如 `extra.typing`），或并入全量快照。

### F4（中）学生提交的作品文件不在备份内

- **位置**：`_sub_snapshot()` 只读 `config.json` / `roster.json` / `submissions.json` 三个 JSON；`submissions/enh/uploads/` 的文件没有打包
- **影响**：换机后提交记录都在、点开作品 404；老师以为"数据迁过来了"。
- **建议**：把 `enh/uploads` 与作品目录并入课程资料包（或单出一个"提交附件包"），并在恢复向导里与 JSON 备份配对。

### F5（低）未知表名静默丢弃

- **现象**：`{"tables": {"不存在的表": [...]}}` → `200 {"ok": true, "counts": {}}`
- **影响**：新版备份在旧版程序上恢复时，新增表会被无声丢弃，用户完全无感。
- **建议**：返回 `unknown: [...]` 与 `skipped` 列表，前端在结果提示里展示。

## 四、兼容性与完整性风险（代码审查，未在本次执行）

以下属于**读了实现但无法在无浏览器 / 无 Node 环境执行**的部分，逐条列出以便决策：

| # | 风险 | 说明 |
|---|---|---|
| R1 | `.cwbackup` 加密层未实机验证 | 浏览器端 PBKDF2-SHA256（15 万次）+ AES-CBC + HMAC-SHA256，外壳带随机盐，格式 `{app:'cw-backup', v:3, enc:true, salt, count, payload}`。换机解密依赖**文件里的盐**，这是正确设计；但本次无法执行 JS，只做了代码审查 |
| R2 | 校验和只覆盖本机数据 | `sum` 只对 `localStorage` 的 `wb-*` 计算，`server` 段没有独立校验和，仅靠外层 HMAC 保护；一旦外层被正确解密，服务端表**无法自校验** |
| R3 | 服务端导入接口无版本门禁 | 版本检查只在浏览器 `apply()` 里（`dump.version > 3` 拒绝）；直接调 `/api/v2/admin/import` 不校验版本，跨版本数据可被写入 |
| R4 | 教师密码随备份走 | `config.teacher` 含口令哈希，换机后必须用**原设备密码**登录；忘了只能用 `--reset-password` 重置。恢复前应提示用户 |
| R5 | 本机偏好不会整体替换 | 前端 `apply()` 只清 `wb-db-*` 前缀的键，`wb-todos-local`、课件视图偏好等非表数据不从备份覆盖 |
| R6 | QuickForm 数据完全不在备份内 | `quickform.db`（表单、任务、学生提交）在独立数据卷，导入本备份后 `/qf/` 是空的，需单独迁移卷 |
| R7 | 前端"先本机后服务端" | 服务端导入失败时，本机 localStorage 已被替换，提示"刷新后可重试"，但界面没有重试按钮，只能整包再导一次（幂等，安全） |
| R8 | 大数据量未压测 | 浏览器 localStorage 通常 5 MB 上限，历史数据多时 `apply()` 会抛配额错误（有提示但无法完成导入） |

## 五、换机前的正确操作（按现状必须遵守）

1. **两台一起备**：教师端 → 系统设置 → 数据与备份 →① 全量加密导出（`.cwbackup`）② 导出课程资料包（`.zip`）
2. 手动补两份"备份没覆盖"的数据：
   - `数据目录/typing.json`（打字练习进度）
   - `数据目录/submissions/enh/uploads/`（学生提交的作品文件）
   - 若用了 QuickForm：单独备份 `quickform-data` 卷
3. 新设备先 `docker compose up -d` 起来 → 打开 `/teacher/` 设账号 → 系统设置 → **从备份一键恢复** → **导入课程资料包**
4. 把第 2 步手工备份的文件放回新设备对应目录，重启容器
5. 核对：班级数、学生数、成绩条数、课件能打开、学生能用原密码登录

## 七、修复结果（2026-11-03 同日实施）

### 改了什么

| 缺陷 | 处理 | 位置 |
|---|---|---|
| **F1** 空表/缺表清库 | 导入前先校验：无可识别表、本机有数据而备份 0 行、数据量不足本机四成（本机 ≥5 行时）一律**在动数据之前**中止；数据量骤减返回 409 要求二次确认，前端弹「仍然导入」后再带 `force` 重试。同时**只替换备份里确实带了的表**，备份没带的表原样保留 | `app/core/store.py::import_snapshot`、`app/server.py::_import` |
| **F2** 口令表只增不清 | 备份里带 `creds` 字段时先 `clear_creds()` 再写入；不带则完全不动 | `app/server.py::_import` |
| **F3** 打字数据不备份 | 全量导出带 `typing`（整份 `typing.json`），导入时整份替换并落盘 | `app/server.py::_typing_snapshot/_typing_restore` |
| **F4** 作品附件不备份 | 导出时把提交数据目录下的附件按相对路径 base64 打包（单文件 ≤10MB、合计 ≤40MB，超出部分**点名回报**），导入时写回本机并修复 `uploads_index.json` 里的旧绝对路径 | `app/server.py::_sub_files_snapshot/_sub_files_restore/_fix_upload_index` |
| **F5** 未知表静默忽略 | 响应里返回 `skipped_tables` / `kept_tables` / `warnings`，前端在恢复结果里展示 | `app/server.py::_import` |
| 前端错误提示不清晰 | 失败改为**弹窗**并区分原因（登录失效 / 服务未启动 / 文件损坏 / 密码错 / 数据量异常 / 本机已还原但服务端失败）；导出密码改为一个弹窗输两遍 | `app/backup.js` |
| 带附件时 413 | 导入接口单独放宽请求体上限到 96MB，并给出可读的超限提示 | `app/server.py::Handler._read_json` |
