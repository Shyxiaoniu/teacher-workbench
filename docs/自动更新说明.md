# 在线更新使用说明（2026-11-04）

教师端 **设置 → 软件更新** 可检查并安装新版本。更新只替换程序文件，
`app/data`（数据库 / 上传 / 课件库 / 配置）**原地保留**，班级、学生、成绩不受影响。

## 一、老师怎么用

1. 打开 **系统设置 → 软件更新**，点「检查更新」（后台默认每 24 小时也自动检查一次）。
2. 发现新版本会显示版本号、发布日期与更新说明，点「下载并安装」。
3. 安装完成后点「立即重启服务」生效（也可稍后手动重启，重启前一切照旧）。
4. 更新失败时：
   - 下载/校验阶段失败 → 什么都不改，直接重试即可；
   - 换装阶段失败 → **自动回滚**到原版本，页面会给出说明；
   - 装完想退回 → 卡片下方有「回滚到更新前」，回滚后重启即可。

## 二、更新源配置（设置 → 软件更新 → 更新源设置）

- **源地址**：指向仓库根目录 `version.json`（manifest）的 URL。留空 = 默认
  `https://gitee.com/shyxiaoniu/teacher-workbench/raw/main/version.json`。
- **访问令牌**：仓库是私有时必填。Gitee 在「设置 → 私人令牌」生成，勾
  `projects` 权限即可；GitHub 用 fine-grained token（Contents 读权限）。
  令牌只存本机服务端配置（`app/data/config.json`），不上传。
- **检查开关 / 间隔**：自动检查默认开，间隔 1~720 小时可调。

## 三、发布一次更新要做什么（开发者 / 牛哥）

1. 改完代码，把 `app/server.py` 的 `VERSION` 提到新号（如 `2.1`）。
2. `python tools/make_release.py` —— 会自动产出 dist 包，并**同步生成仓库根的
   `version.json`**（版本号 / 日期 / zip 文件名 / sha256；`notes` 字段保留上次写的
   更新说明，发布前手工编辑它，一行一条）。
3. 把包推上更新源并提交 manifest：
   ```bash
   git add -f dist/班级工作台<版本>-<yyMMdd>.zip   # *.zip 默认被忽略，-f 强制
   git add version.json
   git commit / push（Gitee + GitHub）
   ```
   zip 与 version.json 放在同一目录（仓库根的 dist/ 下，raw 地址同目录解析）；
   也可以把 zip 传到 Gitee Release，再把 `version.json` 的 `zip` 字段改成完整 URL。
4. 用户端 24 小时内自动收到，或手动「检查更新」立即看到。

## 四、机制细节（给维护者）

| 环节 | 实现 |
|---|---|
| 版本比较 | `app/updater.py::vtuple`，逐段数字比较（`2.0` < `2.1.3`） |
| 下载校验 | sha256（manifest 提供）；Content-Length 不齐也判失败 |
| zip-slip | 解压逐条路径校验，绝对路径 / `..` 一律丢弃 |
| 包结构校验 | 自动定位包内 `app/`（第一层可为包名目录），并核对包内 `server.py` 的 VERSION 与 manifest 一致，防装错包 |
| 备份 | 换装前把 `app/`（除 `data`、`__pycache__`）搬进 `data/update/backup-v<旧版本>-<时间戳>/` |
| 失败回滚 | 换装抛错时自动把备份搬回去；手动回滚走 `/api/v2/update/rollback`（会撤掉 pending 标记） |
| 重启 | `/api/v2/update/restart` 用 `os.execv` 原地换进程映像，端口自动重绑；前端断开后轮询 `/api/v2/state` 恢复。execv 失败（个别安全策略）时返回手动重启指引 |
| 数据安全 | 换装永远不动 `app/data`；测试请用 app 副本起实例（见 `E:\wb-shots\run_updtest.py`） |
