# 课堂系统工作流程 v2 —— 学生机可联网版

> 2026-11-01 · 依据最新确认：**学生机可联网**（可访问互联网），师生机局域网互通，服务端部署在 NAS（Docker 部署，见 README）。
> 本文档是后续逐页重设计的总纲，覆盖：考勤、导学单、提交与统计三大环节。

---

## 〇、架构前提（本次修正）

| 项 | v1 假设 | v2 修正 |
|---|---|---|
| 学生机网络 | 不能访问互联网 | **可联网** |
| 学生端数据链路 | 学生→教师端→服务端（二跳中转） | **学生端直连服务端（NAS）**，教师端订阅服务端事件做实时展示 |
| 时间基准 | 各端本地时钟 | **服务端时间为唯一时间源**（学生机改时钟无法作弊；三端显示前先与服务端校时） |
| 提交 API | 依赖外部部署 | **服务端启动后自动拉起 quick form**，地址由教师端显示 |

- **不做本地兜底服务**：服务端全部跑在 NAS 容器里，教室里的电脑只当客户端用。NAS 短暂不可达时，页面显示"服务未连上、正在重试"，不做另起进程的降级（避免出现两份数据源、事后对不上）。
- 三端角色：**服务端**（NAS）= 身份库 + 课表 + 时间源 + quick form 托管 + 提交存储 + 实时事件推送；**教师端** = 课前准备、课中监控、课后结算；**学生端** = 登录签到、打开导学单、作答提交、查看反馈。

## 一、环节一：考勤

### 1.1 流程步骤

1. **入口发放**：教师端启动后，首页"学生入口"卡显示局域网/服务端地址；教师一键发放到学生机（浏览器打开学生端登录页）。
2. **学生登录**：上课时间到，学生用本人账号（学号）登录学生端；服务端以学生信息库**自动匹配身份**（班级、姓名、学号、座位号），学生无需选择班级。
3. **登录即签到**：登录成功即产生"在线 + 签到"事件，服务端实时推送教师端：
   - 座位表：**已签到学生的座位卡高亮（点亮描边）**，未签到学生座位**呈灰色非高亮**；
   - 在线人数实时更新。
4. **迟到判定**：登录时刻 > 课表上课开始时间 + 5 分钟 → 记**迟到**（记录签到时间戳）。
5. **缺勤判定**：上课开始 + 15 分钟仍未登录，且教师未给该生标记请假 → 服务端自动记**缺勤**，同时推送给两端：教师端座位卡标红、学生端登录后显示缺勤提示。
6. **请假标记**：教师可随时给缺勤/迟到学生标记**病假 / 事假**，标记后覆盖对应状态。
7. **课后结算**：下课时间到，本节课考勤**冻结为快照**；教师在座位表页查看**本节课考勤统计**（出勤/迟到/病假/事假/缺勤人数）与**明细**（每生：状态 + 签到时间 + 标记人与标记时间）。

### 1.2 关键判定规则

| 状态 | 判定条件 | 说明 |
|---|---|---|
| 出勤 | 上课后 0~5 分钟内登录 | 默认状态 |
| 迟到 | 上课后 **>5 分钟**才登录 | 记录实际签到时间 |
| 请假（病/事） | **教师手动标记** | **优先级最高**，覆盖迟到/缺勤；冻结前补标同样生效 |
| 缺勤 | 上课后 **15 分钟**未登录 且 无请假标记 | 即时判定并推送两端；**该生之后若登录，状态自动改为"迟到"**，明细保留"曾记缺勤"的历史记录 |

- **未排课时段不判定**：以课表为时间源，当前时段无排课则本节不产生考勤；连堂课每节独立判定。
- **状态不回退**：考勤状态一经记录不因掉线/刷新回退，只有教师手动修改（改请假/补登）才会变更。
- **中途掉线**：不影响已记录的签到状态；"在线"是实时状态，"考勤"是结论状态，二者分离。

## 二、环节二：导学单

### 2.1 教师课前准备

1. **设计**：教师端显示 quick form 的 API 地址（服务端启动后自动拉起）。教师据此在 quick form 中**自行设计交互式导学单网页**：问卷题、截图上传、其他文件上传等各类交互均可配置；所有供学生查看和下载的资源都在导学单中配置，并**可添加对应资源的副本链接**（防止单一链接失效）。
2. **导入**：教师将设计好的导学单（链接/导出配置）导入教师端，保存为一份"本节课导学单"。
3. **一键匹配学生**：下发时**一键匹配本班学生信息**——服务端生成本班花名册与该导学单的绑定会话，学生打开导学单时身份自动注入（姓名/学号/班级免填），提交自动归属到人。
4. **下发**：点击"下发"，导学单推送到本班全部在线学生端（状态 draft → published，记录下发时间）；学生端"今日"页弹出本节课导学单卡片。

### 2.2 学生端使用

1. 登录后"今日"页按课表节次显示本节课导学单；
2. 点击打开，加载导学单网页（quick form 渲染），身份已自动注入；
3. 按题目作答：问卷选择/填空、截图上传（调起截图或选图）、文件上传等；
4. 提交后学生端显示**回应提示**（见环节三）。

## 三、环节三：提交与统计

### 3.1 提交通路

- 学生端所有提交（问卷回答、截图、文件）**直接调用服务端 quick form 的提交 API**；
- quick form 接收后：① 存储提交内容与文件；② 产生**提交事件**（学生、题号、类型、时间）推送给教师端。

### 3.2 教师端实时统计

- **总览**：已提交人数 / 应提交人数、未交名单（实时刷新）；
- **分题**：每题回答分布（选项占比、正确率如可判分）、截图/文件提交缩略列表；
- **明细**：谁、何时、提交了什么，可点开查看单个学生的作答；
- **催交**：对未交学生可一键催交 → 服务端推送 → 学生端弹提醒。

### 3.3 学生端反馈

- 提交成功 → 学生端 toast"老师已收到 ✅"，题目状态点变绿；
- 教师催交 → 学生端弹出提醒卡片；
- 教师讲评阶段，学生端可收到教师勾选的典型作答展示（预留）。

## 四、一节课完整时间线（示例：10:00–10:45）

| 时间 | 动作 | 端 |
|---|---|---|
| 09:50 | 教师端登录 → 显示学生入口 → 发放网址 | 教师 |
| 09:55 | 学生机开机进学生端登录页 | 学生 |
| 10:00 | 上课铃，学生陆续登录 → 座位表逐一点亮 | 双端实时 |
| 10:05 | **迟到线**：此后登录者记迟到 | 服务端自动 |
| 10:15 | **缺勤线**：未登录且未请假者记缺勤，两端同步 | 服务端自动 |
| 10:16 | 教师下发导学单 → 学生端弹出，开始作答 | 教师→学生 |
| 10:20–10:40 | 学生提交（问卷/截图/文件）→ 教师端统计实时跳动 | 学生→服务端→教师 |
| 10:40 | 教师按统计讲评，可催交 | 教师 |
| 10:45 | 下课 → 考勤冻结，座位表页可查本节统计与明细 | 服务端/教师 |

## 六、待确认的边缘规则（默认按本文执行，可改）

1. **15 分钟线后到堂**：缺勤自动改判"迟到"，明细保留缺勤历史 —— 如希望"迟到即缺席不区分"，可改为保持缺勤仅补签到时间。
2. **无课表排课的临时课**：教师可手动"开始上课"并设定时长，作为课表的补充判定源。
3. **学生迟到是否影响导学单**：不影响，导学单下发后所有在线学生都能收到。
4. **同一学生多设备登录**：以最新一次为准，旧会话自动下线。
